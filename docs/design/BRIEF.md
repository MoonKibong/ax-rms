# 디자인 기준 — Workforce Planner (ax-rms)

근거는 `docs/requirements/REQ-CONTEXT.md`(요구사항 해시 `05adf64fd220a673cd651b5ecf99bbfeeb2d4f62`)다. 요구사항이 정하지 않아 이 문서가 고른 값에는 `(제안)`을 붙인다. 표 머리에 `(제안)`이 있으면 그 표의 값은 모두 제안이다.

## 1. Direction

- **느낌**: 차분하고, 정돈되고, 숫자가 잘 읽히는 업무 도구 (제안).
- **사용자** (D9, D25, D29):
  - 인력 관리자와 프로젝트 관리자: 주로 데스크톱에서 표와 숫자를 비교하고 등록·수정·배치한다.
  - 직원: 주로 모바일에서 자기 정보를 확인한다.
- **원칙** (제안):
  - 한 화면에 한 가지 일을 한다.
  - 상태는 색만으로 구분하지 않고 항상 글자를 함께 쓴다.
  - 투입률과 가용률은 API 값을 그대로 같은 형식으로 보여 준다(D36).
  - 오류 원인은 입력 바로 아래에 둔다(D33).

## 3. Components

모든 상호작용 요소의 공통 규칙:

- **포커스**: `:focus-visible`이면 `outline: var(--focus-ring-width) solid var(--color-focus)`, `outline-offset: var(--focus-ring-offset)`.
- **전환**: `transition`은 색에만 120ms를 쓰고, 크기와 위치는 바꾸지 않는다 (제안).

### 3.1 Button — T#4

| 변형 | 기본 | hover | 쓰는 곳 |
|---|---|---|---|
| `primary` | 배경 primary, 글자 on-primary | 배경 primary-hover | 화면의 주된 동작 하나(저장, 배치) |
| `secondary` | 배경 surface, 글자 text, 테두리 1px border-strong | 배경 surface-subtle | 취소, 필터 초기화, 다시 시도 |
| `danger` | 배경 danger, 글자 on-primary | 배경 danger-hover | 배치 해제처럼 되돌리기 어려운 동작 |

- **크기**: 높이 `--control-height`(40px), 좌우 패딩 `--space-4`(16px), 반경 `--radius-sm`, 글자 sm/600. 라벨은 한 줄이다.
- **disabled**: 변형과 관계없이 배경 disabled-bg, 글자 disabled-text, 테두리 없음, `cursor: not-allowed`.
- **loading**:
  - `aria-busy="true"`이고 클릭을 받지 않는다.
  - 라벨 글자는 DOM에 남기되 `visibility: hidden`으로 감춘다. 그 자리 가운데에 16px 회전 표시를 겹쳐 그린다. 색은 그 변형의 글자색이다.
  - 그래서 너비는 같은 라벨의 보통 버튼과 같다.
  - 회전 표시는 `prefers-reduced-motion`에서 멈춘다.
- **error**: 버튼 자체에는 오류 상태가 없다. 동작 실패는 해당 입력이나 화면의 오류 메시지로 보여 준다.

### 3.2 TextField — T#4

- **라벨**: 입력 위에 둔다. sm/600, 글자 text, 아래 간격 `--space-1`(4px).
  - 필수 항목은 라벨 뒤에 `*`를 붙인다(danger 색, `aria-hidden`). 입력에는 `required`를 둔다.
- **입력**:
  - 높이 40px, 좌우 패딩 `--space-3`(12px), 배경 surface, 테두리 1px border-strong, 반경 `--radius-sm`, 글자 md/400.
  - placeholder는 text-muted이고, 라벨을 대신하지 않는다.
- **도움말**: 입력 아래 `--space-1` 간격에 xs, text-muted로 쓴다(선택).
- **hover**: 테두리 text-muted.
- **focus**: 공통 포커스 표시.
- **disabled**: 배경 disabled-bg, 글자 disabled-text.
- **error** (D33):
  - 테두리를 danger로 바꾼다.
  - 메시지는 입력 바로 아래 `--space-1`(4px) 간격, 왼쪽 끝을 입력과 맞춘다. sm/400, 글자 danger. 앞에 16px 경고 아이콘(인라인 SVG)을 둔다.
  - 입력에는 `aria-invalid="true"`와 메시지 id를 가리키는 `aria-describedby`를 둔다.
  - 도움말이 있으면 오류 메시지가 그 자리를 대신한다.
- **이후 태스크** (같은 규칙으로 만든다): 숫자 입력과 날짜 입력, 선택 상자(`select`).
  - 숫자 입력은 투입률에 쓰며 `step=5`, `min=5`, `max=100`이다(D14).
  - 날짜 입력은 브라우저 기본 `type="date"`를 쓴다.
  - 선택 상자는 TextField와 같은 높이·테두리·오류 규칙을 따른다.

### 3.3 DataTable — T#4

- **넓은 구간**(≥1024px):
  - 표 바깥은 surface, 테두리 1px border, 반경 `--radius-md`.
  - 머리글 행: 배경 surface-subtle, 글자 sm/600 text-muted, `th scope="col"`.
  - 데이터 행: 최소 높이 `--row-min-height`(44px), 셀 패딩 `--space-3` `--space-4`(12px 16px), 행 사이 1px border.
  - 글자는 sm/400 text이다.
  - 행 전체가 링크면 hover 배경이 surface-subtle이고 커서는 pointer다. 링크 자체는 첫 열의 이름이다.
- **숫자 열**(%, 인원, 년): 끝 정렬, `tabular-nums`. 머리글도 끝 정렬이다.
- **좁은 구간**(<1024px):
  - 행마다 카드 하나가 된다. 카드는 surface, 테두리 1px border, 반경 `--radius-md`, 패딩 `--space-4`, 카드 사이 `--space-2`(8px)다.
  - 첫 열 값이 카드 제목이다(md/600).
  - 나머지 열은 "라벨 — 값" 줄이다. 라벨은 sm text-muted로 왼쪽에, 값은 sm text로 오른쪽에 둔다. 숫자 값은 끝 정렬이다.
  - 표 안팎 모두 가로 스크롤이 없다.
- **긴 값**: 5절 "긴 값"을 따른다(줄바꿈, 말줄임 없음).
- **빈 행**: 표 자리에 넘겨받은 StateMessage를 그린다. 머리글도 그리지 않는다.
- **loading**: 표 자리에 Spinner 24px와 "불러오는 중…"(sm, text-muted)을 가운데 둔다. 영역에는 `aria-busy="true"`를 둔다 (제안).

### 3.4 StateMessage — T#4 (D35)

세 종류를 아이콘, 제목, 설명으로 구분한다. 화면은 제목과 설명을 화면에 맞게 바꿀 수 있지만, 아이콘과 색은 바꾸지 않는다.

| 종류 | 아이콘(인라인 SVG, 32px) | 기본 제목 | 기본 설명 | 동작 |
|---|---|---|---|---|
| `empty` | 빈 상자, text-muted | 표시할 항목이 없습니다 | 아직 등록된 데이터가 없습니다. | 없음(화면이 등록 버튼을 넘길 수 있다) |
| `no-results` | 돋보기, text-muted | 검색 결과가 없습니다 | 검색어나 필터를 바꿔 다시 찾아보세요. | `onReset`이 있으면 secondary "필터 초기화" |
| `error` | 경고 삼각형, danger | 데이터를 불러오지 못했습니다 | API가 준 메시지, 없으면 "잠시 후 다시 시도하세요." | `onRetry`가 있으면 secondary "다시 시도" |

- **블록**: 가운데 정렬, 패딩 `--space-6` `--space-4`(32px 16px), 배경 surface, 테두리 1px border, 반경 `--radius-md`.
- **글자**: 제목 md/600 text, 설명 sm text-muted. 아이콘·제목·설명·버튼 사이는 `--space-2`(8px)다.
- **접근성**: `error`는 `role="alert"`이다. `empty`와 `no-results`는 `role="status"`이다.

### 3.5 AppShell — T#4

6절 Layout을 따른다. 내비게이션 링크의 현재 항목에는 `aria-current="page"`를 둔다.

### 3.6 이후 태스크가 같은 기준으로 만드는 것

- **Badge(상태 표시)**:
  - 공통: xs/600, 패딩 `2px 8px`, 반경 `--radius-full`. 글자를 항상 쓴다.
  - 직원 상태: `투입 가능` success/success-bg, `투입 불가` danger/danger-bg.
  - 배치: `확인 필요` warning/warning-bg (D21).
  - 프로젝트 상태(D13): `계획` text-muted/surface-subtle, `진행 중` primary/surface-subtle, `완료` success/success-bg, `보류` warning/warning-bg.
  - 대시보드: `인력 부족` warning/warning-bg.
- **숫자 타일(대시보드)**: surface 카드, 패딩 `--space-4`, 라벨 sm text-muted, 값 2xl/700 `tabular-nums`, 단위 sm text-muted(예: `20` `명`). 타일 전체가 관련 목록으로 가는 링크다.
- **Gantt (T#12, D15)**:
  - 행은 배정 하나다. 머리는 프로젝트명이다. 막대 안에는 글자를 쓰지 않는다.
  - 기간과 투입률(`2026-10-01 ~ 2026-12-31 · 60%`, xs)은 그 막대 바로 아래 줄에 쓴다.
  - 막대 색: 진행 중 프로젝트 배정은 primary 배경, 그 밖의 배정은 surface-subtle 배경에 테두리 1px border-strong이다.
  - 겹침 구간마다 자기 줄을 둔다. 트랙에 그 구간만큼의 띠(최소 2px, warning-bg 배경에 1px warning 테두리)를 그리고, 그 아래 줄에 그 구간의 합계 %를 xs, warning으로 쓴다. 겹치는 배정의 막대는 각자의 줄에 있다.
  - 오늘 위치는 1px danger 세로선이다. "오늘" 글자는 월 눈금 줄 위의 자기 줄에 쓴다.
  - 위쪽 축에 월 눈금 글자(`10월`, xs, text-muted)를 쓴다. 앞에 보인 눈금 글자와 트랙 위 거리가 40px 미만이면 그 눈금 글자는 생략한다(눈금 위치는 그대로).
  - 모든 글자 상자는 트랙의 왼쪽·오른쪽 끝 안에 있고 서로 겹치지 않는다. 글자는 줄바꿈하고 말줄임표는 쓰지 않는다. 글자 상자는 막대(또는 겹침 구간, 오늘)의 가운데에 맞추되, 끝을 넘으면 끝에 붙인다.
  - 차트 바탕은 surface이고 너비는 부모 너비에 맞춘다. 360px에서도 가로 스크롤 없이 기간을 압축한다 (제안).
- **확인 대화상자(배치 해제)**: 브라우저 `confirm`이 아닌 화면 안 대화상자다. 제목, 대상(직원·프로젝트·기간), secondary "취소", danger "해제" 순서다 (제안).

## 4. Layout

breakpoint는 **1024px 하나**다 (제안).

- **넓은 구간**: `min-width: 1024px`. 1280px(D29 데스크톱 기준)이 여기 속한다.
- **좁은 구간**: `max-width: 1023px`. 360px(D29 모바일 기준)이 여기 속한다.

CSS 사용자 정의 속성은 media query에 쓸 수 없으므로, 1024는 media query 안에 숫자로 쓴다.

**넓은 구간** (≥1024px):

- `header`(banner):
  - 화면 위 전체 너비, 높이 56px, 배경 surface, 아래 테두리 1px border.
  - 왼쪽에 앱 이름 "Workforce Planner"(lg/700, text)를 둔다.
  - 오른쪽은 사용자 영역(T#6)이다.
- `nav`(navigation):
  - header 아래 왼쪽, 너비 220px, 배경 surface, 오른쪽 테두리 1px border, 패딩 `--space-3`.
  - 항목은 세로 목록이고, 각 항목은 높이 40px, 패딩 `0 --space-3`, 반경 `--radius-sm`, 글자 sm/600 text다.
  - hover는 배경 surface-subtle이다.
  - 현재 항목은 배경 surface-subtle, 글자 primary, 왼쪽 3px primary 막대다.
- `main`: nav 오른쪽. 배경 bg, 패딩 32px, 안쪽 내용 최대 너비 1200px(왼쪽 정렬).
- **1280px에서의 너비**: 1280 − 220 = 1060, 1060 − 64 = 996px. **1024px에서**: 1024 − 220 − 64 = 740px.

**좁은 구간** (<1024px):

- `header`: 높이 56px. 앱 이름은 md/700이다.
- `nav`: header 바로 아래의 가로 탭 막대다. 같은 `nav` 요소가 모양만 바꾼다.
  - 높이 44px, 배경 surface, 아래 테두리 1px border.
  - 항목들은 너비를 똑같이 나눈다(`flex: 1`). 글자는 sm/600 text-muted, 가운데 정렬이다.
  - 현재 항목은 글자 primary, 아래 2px primary 막대다.
- `main`: 패딩 16px.
- **360px에서의 너비**: 360 − 32 = 328px. 탭 3개는 각 120px(예: "대시보드" 4자 약 56px)이라 들어간다. 1023px에서는 991px이다.

**공통**:

- header와 nav는 스크롤해도 따라오지 않는다(`position: static`) (제안).
- `body`의 배경은 bg, 글자는 md/400 text, 글꼴은 `--font-family-base`다.

**내비게이션 항목** (경로는 T#6이 라우터로 연결한다) (제안):

| 항목 | 경로 | 보이는 역할 (T#6, D25) |
|---|---|---|
| 대시보드 | `/` | 인력 관리자, 프로젝트 관리자 |
| 직원 | `/employees` | 인력 관리자, 프로젝트 관리자 |
| 프로젝트 | `/projects` | 인력 관리자, 프로젝트 관리자 |
| 내 정보 | `/me` | 직원 역할만 가진 계정(그 계정은 이 항목만 본다) |

T#4의 참조 화면은 로그인 전이라 앞의 세 항목을 보여 주고, "대시보드"를 현재 항목으로 둔다.

## 5. Formats

| 대상 | 형식 | 정렬 | 근거 |
|---|---|---|---|
| 날짜 | `YYYY-MM-DD` (예: `2026-10-13`) | 표에서 시작 정렬, `tabular-nums` | (제안) |
| 기간 | `2026-10-01 ~ 2026-12-31` (`~` 앞뒤 공백 한 칸). 좁은 너비에서는 `~` 뒤에서 줄바꿈 | 시작 정렬 | (제안) |
| 월 | `2026-10`. 간트 축에는 `10월` | 시작 정렬 | (제안) |
| 투입률·가용률 | 정수와 `%`, 사이 공백 없음 (예: `60%`, `0%`, `100%`). 값은 API 그대로 쓴다(D36). 5% 단위(D14) | 끝 정렬, `tabular-nums` | D14, D36 |
| 인원 | 정수. 표에서는 숫자만, 문장과 타일에서는 `명`을 붙인다 (예: `3명`, `필요 5명 / 배치 3명`) | 끝 정렬 | (제안) |
| 경력 | `N년` (예: `7년`) | 끝 정렬 | D12 |
| 1,000 이상 숫자 | 천 단위 쉼표 (`1,234`) | 끝 정렬 | (제안) |
| 금액 | 이 제품에는 금액이 없다 | — | REQ-CONTEXT에 금액 없음 |
| 빈 값 | `—` (em dash), text-muted | 그 열의 정렬 | (제안) |
| 숙련도 | `초급`, `중급`, `고급` | 시작 정렬 | D11 |

**긴 값**: 공백 없이 긴 값(이메일, 긴 프로젝트명, 영문 기술명)은 모두 `overflow-wrap: anywhere`로 칸 안에서 줄바꿈한다 (제안). 말줄임(`…`)은 쓰지 않는다. 그래서 전체 값이 항상 보이고 `title`이 필요 없다. 어떤 값도 칸이나 뷰포트를 넘지 않는다.

## 6. Screens

모든 화면에 공통으로 적용한다.

- **오류**: 화면 데이터를 불러오지 못하면 내용 자리에 StateMessage `error`와 "다시 시도"를 둔다.
- **불러오는 중**: Spinner와 "불러오는 중…"을 둔다.
- **관리 기능** (직원·프로젝트 등록·수정, 직원 상태 변경): 좁은 구간에서는 버튼을 숨긴다(D29). 조회, 대시보드, 배치, 배치 해제는 좁은 구간에서도 된다.

### 6.0 참조 화면 `/` (T#4 전용, 업무 화면이 생기면 대체됨)

- **할 일**: 디자인 시스템의 토큰·셸·컴포넌트를 한 화면에서 확인한다.
- **순서**:
  1. 제목 "디자인 참조"(xl/700).
  2. 백엔드 상태 줄 "백엔드 상태: UP"(sm, text-muted). T#3의 표시를 유지한다.
  3. "버튼" 구역: primary, secondary, danger, disabled, 그리고 같은 라벨 "저장"의 보통 버튼과 loading 버튼을 나란히.
  4. "입력" 구역: 보통 입력 하나(라벨 "이름"), 오류 입력 하나(라벨 "투입률", 값 `120`, 메시지 "투입률은 5%에서 100% 사이로 입력하세요.").
  5. "표" 구역: 직원 표본 4행. 열은 이름 · 부서 · 투입 시작일 · 투입 종료일 · 투입률 · 가용률이다. 한 행의 이름은 공백 없는 48자 영문 값이다.
  6. "상태" 구역: StateMessage `empty`, `no-results`(필터 초기화 버튼), `error`(다시 시도 버튼).
- **구역 배치**: 구역 제목은 lg/600이고 구역 사이 간격은 `--space-6`(32px)이다. 버튼 줄은 `flex-wrap`, 간격 `--space-2`다.
- **좁은 구간**: 구역이 한 열로 쌓이고, 표는 카드가 되며, 버튼은 줄바꿈한다.

### 6.1 로그인 (D16) — T#6

- **할 일**: 계정과 비밀번호로 들어간다.
- **배치**: 셸 없이 가운데 카드 하나다(너비 최대 400px, surface, 패딩 `--space-6`, 반경 `--radius-md`, `--shadow-sm`).
- **순서**: 앱 이름 → 계정 → 비밀번호 → primary "로그인"(전체 너비).
- **상태**:
  - 실패 메시지는 비밀번호 입력 아래 TextField 오류 규칙으로 보인다.
  - 로그인 중에는 버튼이 loading이다.
- **좁은 구간**: 카드가 화면 너비 − 32px가 된다.

### 6.2 통합 대시보드 (D5, D20, D21, D23) — T#18

- **할 일**: 인력 현황을 한눈에 보고, 문제가 있는 직원·프로젝트로 이동한다.
- **순서**:
  1. 숫자 타일 5개: 전체 직원 · 투입 가능 · 투입 불가 · 가용 인원 · 진행 프로젝트.
  2. 확인 필요 배치 목록(warning 배지).
  3. 인력 부족 프로젝트 목록.
  4. 직원별 투입률 목록.
  5. 부서별 평균 투입률.
- **목록 항목**: 직원·프로젝트 상세로 가는 링크다.
- **넓은 구간**: 타일은 5열, 목록은 2열 격자다.
- **좁은 구간**: 타일은 2열(각 160px), 목록은 한 열이다.
- **상태**: 목록마다 따로 보인다(D35).
  - 빈 목록: "확인이 필요한 배치가 없습니다", "인력이 부족한 프로젝트가 없습니다" 등.
  - 오류: 그 목록 자리에 `error`.

### 6.3 직원 목록 (D2) — T#13

- **할 일**: 조건에 맞는 직원을 찾아 상세로 간다.
- **순서**:
  1. 제목 "직원"과 오른쪽 primary "직원 등록"(넓은 구간, 인력 관리자).
  2. 이름 검색.
  3. 필터: 부서, 기술, 투입 상태, 가용률.
  4. 결과 수 "N명".
  5. 표: 이름 · 부서 · 직무 · 기술 · 투입 상태 배지 · 현재 가용률 · 확인 필요 배지.
- **좁은 구간**:
  - 검색은 그대로 보인다.
  - 필터는 secondary "필터" 버튼으로 펼친다. 적용 중인 필터 수를 버튼에 쓴다.

  - `no-results`: "조건에 맞는 직원이 없습니다"와 필터 초기화.

### 6.4 직원 상세·등록·수정 (D2, D6, D15, D24) — T#14

- **할 일**: 한 직원의 정보, 역량, 배치 현황을 확인한다. 인력 관리자는 수정하고 상태를 바꾼다.
- **순서**:
  1. 이름(xl/700), 상태 배지, 현재 가용률.
  2. 기본 정보: 부서, 직무, 경력, 투입 불가 사유, 종료 예정일.
  3. 기술·숙련도 목록.
  4. 배치 현황 간트와 배치 표: 프로젝트 · 기간 · 투입률.
  5. 버튼: "수정", "상태 변경"(넓은 구간, 인력 관리자).
- **등록·수정 폼**:
  - 한 열이다. 필드는 D2 순서를 따르고, 기술은 줄 추가·삭제로 편집한다.
  - 오류는 각 입력 아래 TextField 규칙으로 보인다.
- **상태 변경**: 대화상자에서 상태, 사유(투입 불가일 때 필수), 종료 예정일(선택)을 입력한다.
- **내 정보** (D24): 같은 화면을 읽기 전용으로 보이며, 버튼이 없다.
- **좁은 구간**: 한 열이고, 관리 버튼은 없다.
- **상태**: 배치가 없으면 간트 자리에 `empty` "배치된 프로젝트가 없습니다"를 둔다.

- **순서**:
  1. 제목 "프로젝트"와 primary "프로젝트 등록"(넓은 구간, 프로젝트 관리자).

- **상태**:
  - `empty`: "등록된 프로젝트가 없습니다".
  - `no-results`: "이 상태의 프로젝트가 없습니다".
  - `error`.

### 6.6 프로젝트 상세·등록·수정 (D3, D22, D30) — T#16

- **할 일**: 프로젝트의 정보, 필요 역량, 배치 인력을 확인한다. 프로젝트 관리자는 수정하고 배치 화면으로 간다.
- **순서**:
  1. 프로젝트명, 상태 배지, 기간.
  2. 설명.
  3. 인력 현황: "필요 5명 / 배치 3명"과 부족한 역량.
  4. 필요 역량 표: 직무 · 기술 · 숙련도 · 인원.
  5. 배치 인력 표: 직원 · 기간 · 투입률.
  6. 버튼: primary "인력 배치"(두 구간 모두), "수정"(넓은 구간).
- **폼**:
  - 필요 역량은 줄 추가·삭제로 편집한다.

- **상태**: 배치 인력이 없으면 `empty` "배치된 직원이 없습니다".

### 6.7 프로젝트 인력 배치 (D8, D14, D15, D27, D28, D33) — T#17

  5. 투입률 입력(5% 단위)과 primary "배치".
  6. 현재 배치 목록: 직원 · 기간 · 투입률 · "수정" · danger "해제".

## 7. Checks

리뷰어는 `docs/screens/T4/reference-1280.png`와 `reference-360.png`를 다음 항목·값과 대조한다. e2e(T#4 기준 8–10)가 재는 값은 "e2e"로 표시했다. 이후 화면 태스크는 해당 화면의 PNG에 7–10을 적용하고, 간트를 그리는 화면은 13도 적용한다.

1. **배경과 면**: 페이지 배경 `#F6F7F9`, 카드·표·입력 면 `#FFFFFF`, 표 머리글 `#EEF1F5`.

   - header 높이 56px, 흰 배경, 아래 1px 구분선.
   - 왼쪽 nav 너비 220px, 세로 항목. "대시보드"가 현재 항목(옅은 면, 주색 글자, 왼쪽 3px 주색 막대).

4. **360px 셸**:

   - 투입률·가용률 열은 오른쪽 정렬이고 숫자 끝이 세로로 맞는다(e2e).
