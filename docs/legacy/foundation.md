# Workforce Planner (ax-rms) Foundation

### EXPLANATION

본 시스템의 목적은 30~100명 규모 조직 내에서 직원의 역량-업무량 간의 불균형을 해소하고, 데이터 기반의 인력 배치를 실현하는 것입니다. 

가장 중요한 설계 결정은 **기간 기반의 투입률 합산 모델**입니다. 단순히 현재 시점의 가용 여부를 따지는 것이 아니라, 특정 프로젝트 수행 기간 전반에 걸쳐 타 프로젝트와의 중복 투입률을 계산하여 100% 초과 배정을 원천 차단합니다. 이는 인적 자원의 과부하를 방지하고 계획의 신뢰도를 높이기 위한 조치입니다.

기술적으로는 2일이라는 매우 짧은 개발 기간과 소규모 조직 특성을 고려하여, 설정이 간편하고 이식성이 높은 **SQLite**를 데이터베이스로 채택하였습니다. 쓰기 잠금(Lock) 이슈가 발생할 수 있으나, 동시 접속자가 적은 인력 관리 도구 특성상 생산성 이득이 더 크다고 판단했습니다. 또한, 비즈니스 로직의 복잡도가 높은 가용률 계산 및 검증 루틴은 백엔드의 서비스 레이어에서 원자적으로 처리하여 데이터 정합성을 보장합니다.

### CONTRACT

**[C-REQ-01] 직원 상태 및 기본 관리**
- 인력 관리자는 직원 정보를 등록하고 수정한다.
- 직원은 `투입 가능` 또는 `투입 불가` 상태를 가진다.
- 시스템은 투입 불가 상태인 직원의 신규 배치를 차단한다.
- 시스템은 기존 배정이 있는 투입 불가 직원을 `확인 필요`로 표시한다.
- 인력 관리자만이 직원 상태를 변경할 수 있다.
-- 체크: 투입 불가 직원을 배치 시도 시 에러 메시지가 출력되는가? (Pass/Fail)

**[C-REQ-02] 프로젝트 및 역량 정의**
- 프로젝트 관리자는 프로젝트의 필요 직무, 기술, 숙련도를 정의한다.
- 시스템은 프로젝트의 시작일과 종료일을 필수 값으로 관리한다.
- 시스템은 프로젝트 상태별 필터링 기능을 제공한다.
-- 체크: 프로젝트 기간 설정 없이 저장 시도 시 유효성 검사 오류가 발생하는가? (Pass/Fail)

**[C-REQ-03] 인력 배치 및 가용률 검증**
- 프로젝트 관리자는 대상 기간, 투입률을 지정하여 직원을 배치한다.
- 시스템은 $\text{현재 투입률 합계} + \text{신규 투입률} \le 100\%$ 인지 검증한다.
- 시스템은 $\text{직원 상태} = \text{'투입 가능'}$ 인지 검증한다.
- 시스템은 배치 기간이 프로젝트 기간 내에 존재하는지 검증한다.
- 시스템은 검증 통과 시에만 배치를 저장한다.
- 시스템은 배치 해제 시 해당 기간의 가용률을 즉시 복구한다.
-- 체크: 총투입률이 101%가 되는 배치를 저장할 때 차단되는가? (Pass/Fail)
-- 체크: 기간이 겹치지 않는 두 프로젝트의 투입률이 각각 60%일 때 저장이 가능한가? (Pass/Fail)

**[C-REQ-04] 통합 대시보드**
- 시스템은 전체 직원 수 및 상태별 인원 수를 실시간 집계한다.
- 시스템은 인력이 부족한 프로젝트 목록을 표시한다.
- 시스템은 부서별 평균 투입률을 계산하여 출력한다.
- 대시보드의 각 항목은 해당 상세 페이지로 연결된다.
-- 체크: 인력 배치 변경 후 대시보드의 가용 인원 수가 즉시 갱신되는가? (Pass/Fail)

**[C-TECH-01] 기술 제약 사항**
- 서버는 Spring Boot 3.x 이상 및 Java 17 이상 환경에서 구동한다.
- DB는 SQLite 파일을 사용하며 별도의 외부 설치 프로세스를 없앤다.
- 클라이언트는 React와 TypeScript를 사용하여 타입 안정성을 확보한다.
-- 체크: 애플리케이션 실행 시 SQLite 파일이 자동 생성되고 연결되는가? (Pass/Fail)
