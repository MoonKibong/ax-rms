**D2. 직원 정보와 기능.**

**D3. 프로젝트 정보와 기능.**

## 2. 업무 규칙

**D6. 직원 투입 상태.**
상태는 `투입 가능` 또는 `투입 불가`다. 투입 불가로 바꿀 때 사유를 기록하고, 종료 예정일은 선택 입력이다. 종료 예정일이 지나도 상태는 자동으로 바뀌지 않는다. 상태를 바꿔도 기존 배정은 삭제하지 않는다. 상태는 인력 관리자만 바꾼다.
추적: R2 → 없음. 출처: 원문.

**D7. 가용률 계산식.**
가용률 = 100% − 겹치는 기간의 프로젝트 투입률 합계. 기간이 겹치는 배정만 합산한다. 종료된 프로젝트(D19)는 현재 가용률에서 뺀다. 배치를 해제하거나 투입률을 바꾸면 다시 계산한다.
추적: R5 → 없음. 출처: 원문.

**D8. 배치 저장 조건.**
다음을 모두 만족할 때만 배치를 저장한다. 하나라도 어기면 저장을 막고 원인을 보여 준다(D33).
- 직원 상태가 `투입 가능`이다 (신규 배치).
- 대상 기간의 가용률(D18)이 0%보다 크다.
- 저장 후 대상 기간의 어느 날도 총투입률이 100%를 넘지 않는다.
- 배치 기간이 프로젝트 기간 안에 있다.
- 같은 직원·같은 프로젝트에 기간이 겹치는 배정이 없다(D27).
추적: R5, R6 → Q8, Q17. 출처: 원문.

**D9. 역할과 권한.**
- 인력 관리자: 직원 등록·수정, 직원의 기술·숙련도·경력 관리, 직원 상태 변경.
- 프로젝트 관리자: 프로젝트와 필요 역량 등록·수정, 직원 가용률 확인, 배치·투입률 수정·해제.
- 직원: 자신의 프로필·역량·프로젝트·투입률 확인.
추적: §3, R2 "인력 관리자만 상태를 변경할 수 있다.", R4 → Q15. 출처: 원문.

**D10. 검증 시나리오와 성공 기준.**
§7의 여섯 시나리오(정상 배치, 투입률 초과, 투입 불가 직원, 기간이 겹치지 않는 배치, 배치 해제, 상태 변경)가 자동 테스트로 통과한다(D37). §10의 일곱 단계 흐름을 시드 데이터(D31)로 처음부터 끝까지 시연할 수 있다.
추적: §7, §10 → 없음. 출처: 원문.
