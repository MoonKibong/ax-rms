# Workforce Planner 요구사항

## 1. 프로젝트 개요

30~100명 규모 회사에서 직원의 역량과 현재 업무량을 확인하고, 프로젝트에 적합한 인력을 배치하는 웹 시스템을 개발한다.

프로젝트별 투입률을 기준으로 직원의 가용률을 계산하며, 투입 불가능한 직원이나 총투입률이 100%를 초과하는 직원의 신규 배치를 차단한다.

- 개발 기간: 2일
- 개발 방식: NEXI
- 임시 제품명: Workforce Planner

## 2. 해결하려는 문제

- 직원이 현재 투입 가능한지 확인하기 어렵다.
- 직원별 프로젝트와 투입률이 여러 문서에 분산돼 있다.
- 같은 기간에 여러 프로젝트가 중복 배정될 수 있다.
- 직원의 총투입률이 100%를 초과할 수 있다.
- 프로젝트의 필요 역량과 현재 인력 현황을 비교하기 어렵다.
- 회사 전체의 가용 인력과 과부하 현황을 파악하기 어렵다.

## 3. 사용자

### 인력 관리자

- 직원과 부서 정보를 관리한다.
- 직원의 기술·숙련도·경력을 관리한다.
- 직원의 투입 가능 상태를 관리한다.

### 프로젝트 관리자

- 프로젝트와 필요 역량을 관리한다.
- 직원의 가용률을 확인한다.
- 프로젝트에 직원을 배치하거나 해제한다.

### 직원

- 자신의 프로필과 역량을 확인한다.
- 자신의 프로젝트와 투입률을 확인한다.

## 4. 핵심 서비스 흐름

```text
직원 정보 등록
→ 프로젝트 생성
→ 직원 상태·가용률 확인
→ 프로젝트에 직원 배치
→ 기간·투입률 검증
→ 배치 결과 저장
→ 대시보드 갱신
```

## 5. 기능 요구사항

### R1. 직원 관리

직원에게 다음 정보를 관리한다.

- 이름
- 부서
- 직무
- 기술 스택
- 기술별 숙련도
- 경력
- 투입 가능 상태
- 투입 불가 사유
- 투입 불가 종료 예정일
- 참여 프로젝트
- 프로젝트별 투입률
- 현재 가용률

필요 기능:

- 직원 목록·상세 조회
- 직원 등록·수정
- 이름 검색
- 부서·기술·투입 상태·가용률 필터

### R2. 직원 투입 상태

직원은 다음 상태 중 하나를 가진다.

- `투입 가능`
- `투입 불가`

업무 규칙:

- 투입 불가 직원은 신규 프로젝트에 배치할 수 없다.
- 투입 불가 사유를 기록한다.
- 종료 예정일은 선택 입력으로 제공한다.
- 종료 예정일이 지나도 상태를 자동으로 변경하지 않는다.
- 기존 프로젝트 배정은 상태 변경 시 자동 삭제하지 않는다.
- 기존 배정이 있는 투입 불가 직원은 `확인 필요`로 표시한다.
- 인력 관리자만 상태를 변경할 수 있다.

### R3. 프로젝트 관리

프로젝트에 다음 정보를 관리한다.

- 프로젝트명
- 설명
- 시작일·종료일
- 프로젝트 상태
- 필요 직무
- 필요 기술
- 필요 숙련도
- 필요 인원
- 배치된 직원
- 직원별 투입률

필요 기능:

- 프로젝트 목록·상세 조회
- 프로젝트 등록·수정
- 상태별 필터
- 프로젝트별 인력 현황 확인

### R4. 인력 배치

프로젝트 관리자는 프로젝트에 직원을 배치할 수 있다.

배치 정보:

- 직원
- 프로젝트
- 투입 시작일
- 투입 종료일
- 투입률

필요 기능:

- 프로젝트 인력 배치
- 투입률 수정
- 배치 해제
- 직원 상세에서 배치 현황 확인
- 프로젝트 상세에서 배치 인력 확인

### R5. 가용률 계산

```text
가용률 = 100% - 겹치는 기간의 프로젝트 투입률 합계
```

업무 규칙:

- 같은 기간의 총투입률은 100%를 초과할 수 없다.
- 신규 배치 후 100%를 넘으면 저장을 차단한다.
- 기간이 겹치는 배정만 투입률을 합산한다.
- 종료된 프로젝트는 현재 가용률 계산에서 제외한다.
- 배치를 해제하면 가용률을 다시 계산한다.
- 프로젝트 기간 밖으로 직원을 배치할 수 없다.
- 동일 직원·프로젝트·기간의 중복 배정을 허용하지 않는다.

### R6. 최종 투입 가능 판단

다음 조건을 모두 충족할 때 직원을 신규 프로젝트에 배치할 수 있다.

```text
직원 상태가 투입 가능
AND
대상 기간의 가용률이 0%보다 큼
AND
신규 배치 후 총투입률이 100% 이하
```

### R7. 통합 대시보드

대시보드에 다음 정보를 표시한다.

- 전체 직원 수
- 투입 가능 직원 수
- 투입 불가 직원 수
- 가용 인원 수
- 진행 프로젝트 수
- 인력이 부족한 프로젝트
- 직원별 투입률
- 부서별 평균 투입률
- 확인이 필요한 인력 배치

대시보드 항목에서 관련 직원 또는 프로젝트 상세로 이동할 수 있어야 한다.

## 6. 구현 화면

1. 통합 대시보드
2. 직원 목록
3. 직원 상세·등록·수정
4. 프로젝트 목록
5. 프로젝트 상세·등록·수정
6. 프로젝트 인력 배치

## 7. 주요 검증 시나리오

### 정상 배치

기존 투입률 60%인 직원에게 30%를 추가하면 다음과 같이 저장한다.

- 총투입률: 90%
- 가용률: 10%

### 투입률 초과

기존 투입률 60%인 직원에게 50%를 추가하면 총투입률이 110%이므로 저장을 차단한다.

### 투입 불가 직원

가용률이 남아 있더라도 상태가 `투입 불가`이면 신규 배치를 차단한다.

### 기간이 겹치지 않는 배치

기존 프로젝트와 신규 프로젝트 기간이 겹치지 않으면 두 투입률을 동시에 합산하지 않는다.

### 배치 해제

프로젝트 배치를 해제하면 직원의 투입률과 가용률을 다시 계산한다.

### 상태 변경

기존 프로젝트에 배치된 직원을 `투입 불가`로 변경하면 기존 배정은 유지하고 대시보드에 `확인 필요`로 표시한다.

## 8. 기술 스택

- 백엔드/API: Java, Spring Boot
- 프런트엔드: React, TypeScript
- 데이터베이스: SQLite
- 통신: REST API

```text
React + TypeScript
        ↓ REST API
Java + Spring Boot
        ↓
SQLite
```

## 9. 품질 요구사항

- 데스크톱과 모바일에서 핵심 흐름을 사용할 수 있어야 한다.
- 저장 실패와 업무 규칙 위반 원인을 사용자에게 표시해야 한다.
- 빈 목록, 검색 결과 없음과 오류 상태를 제공해야 한다.
- 모든 화면에서 투입률과 가용률이 동일해야 한다.
- 배치 변경 후 관련 화면과 대시보드를 갱신해야 한다.
- 핵심 업무 규칙을 자동 테스트로 검증해야 한다.
- 데모용 직원·부서·프로젝트·배치 시드 데이터를 제공해야 한다.

## 10. 성공 기준

다음 흐름을 처음부터 끝까지 시연할 수 있어야 한다.

1. 직원과 프로젝트를 조회한다.
2. 투입 가능한 직원을 선택한다.
3. 기간과 투입률을 지정해 프로젝트에 배치한다.
4. 직원·프로젝트·대시보드의 현황이 갱신된다.
5. 총투입률 100% 초과 배치를 차단한다.
6. 투입 불가 직원의 신규 배치를 차단한다.
7. 배치를 해제하면 가용률이 복구된다.

## 12. NEXI 진행 순서

1. 새 프로젝트에서 `nexi-init`
2. `Mode: team` 설정
3. 이 문서를 `docs/requirements/REQUEST.md`에 저장
4. `nexi-requirements analyze`
5. `QUESTIONS.md`에 팀 답변
6. `nexi-requirements answers`
7. `nexi-requirements decide`
8. PM이 `REQ-CONTEXT.md` 검토
9. PM이 `nexi-requirements approve`
10. `nexi-backlog`으로 태스크 생성
11. `nexi-design`으로 디자인 기준 승인
12. 태스크별 계약 작성 및 승인
13. 개발자 구현
14. 담당 검토자의 독립 리뷰
15. `APPROVE` 이후 병합
16. 모든 태스크 완료 후 `nexi-finish`

## 13. 요구사항 분석에서 확정할 질문

- 기술 숙련도는 몇 단계로 구분하는가?
- 경력은 전체 경력과 기술별 경력 중 무엇을 관리하는가?
- 프로젝트 상태에는 어떤 값이 필요한가?
- 투입률은 몇 퍼센트 단위로 입력하는가?
- 일부 기간만 겹치는 배정을 화면에 어떻게 표시하는가?
- 역할별 사용자 전환은 어떻게 제공하는가?
- 모바일에서 어느 관리 기능까지 지원하는가?
