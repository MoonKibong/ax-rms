# 질문

구현이나 검증을 막는 질문만 적었다. 대괄호는 `REQUEST.md`의 위치다.
`기존 답:`은 NEXI 이전에 팀이 정리한 답(`docs/legacy/REQ-CONTEXT.md` §1, `docs/legacy/foundation.md`)이다. 아직 확정된 답이 아니며, `answers`에서 근거로 쓴다. `기존 답 없음`은 새로 답해야 하는 질문이다.

Q1. 기술 숙련도는 몇 단계이며, 각 단계의 이름은 무엇인가? [R1 "기술별 숙련도", §13] — 기존 답: 3단계 (legacy REQ-CONTEXT §1.1 "Skill Levels"). 단계 이름은 기존 답 없음.
Q2. 경력은 전체 경력(년)만 관리하는가, 기술별 경력도 관리하는가? [R1 "경력", §13] — 기존 답: 전체 경력(년 수) (legacy REQ-CONTEXT §1.1 "Experience").
Q3. 프로젝트 상태 값은 무엇인가? [R3 "프로젝트 상태", §13] — 기존 답: 계획, 진행 중, 완료, 보류 (legacy REQ-CONTEXT §1.3 "Project Status").
Q4. 투입률은 몇 % 단위로 입력하며, 최솟값과 최댓값은 얼마인가? [R4 "투입률", §13] — 기존 답: 5% 단위 (legacy REQ-CONTEXT §1.2 "Input Precision"). 최솟값·최댓값은 기존 답 없음.
Q5. 일부 기간만 겹치는 배정을 화면에 어떻게 표시하는가? [§13] — 기존 답: 간트 차트 (legacy REQ-CONTEXT §1.2 "Visualization"). 어느 화면에 두는지는 기존 답 없음.
Q6. 로그인과 역할 전환은 어떻게 제공하는가? 비밀번호 로그인, 데모 계정 선택, 화면 상단의 역할 전환 중 무엇인가? [§3, §13] — 기존 답: 역할별 화면은 로그인 때 정해진다 (legacy REQ-CONTEXT §1.4 "Access Control"). 로그인 방식(비밀번호 여부)은 기존 답 없음.
Q7. 한 사용자가 여러 역할을 함께 가질 수 있는가? 사용자 계정은 직원과 1:1로 연결되는가? [§3] — 기존 답: 여러 역할을 동시에 가질 수 있다 (legacy REQ-CONTEXT §1.1 "Roles"). 계정과 직원의 연결은 기존 답 없음.
Q8. 배치 기간 안에서 날마다 가용률이 다를 때, R6의 "대상 기간의 가용률"은 그 기간 중 가장 낮은 날의 값인가? [R5, R6] — 기존 답: 가용률은 일 단위로 계산한다 (legacy REQ-CONTEXT §1.2 "Calculation Granularity"). 기간 대표값은 기존 답 없음.
Q9. "현재 가용률"의 "현재"는 오늘 날짜인가? "종료된 프로젝트"는 상태가 완료인 프로젝트인가, 종료일이 지난 프로젝트인가? [R1 "현재 가용률", R5 "종료된 프로젝트는 현재 가용률 계산에서 제외한다."] — 기존 답 없음.
Q10. "인력이 부족한 프로젝트"의 기준은 무엇이며, 어느 날짜 기준으로 배치 인원을 세는가? [R7] — 기존 답: 배치 인원 < 필요 인원, 또는 필수 기술 보유자 부재 (legacy REQ-CONTEXT §1.3 "Shortage Criteria"). 기준 날짜는 기존 답 없음.
Q11. `확인 필요`는 누가 해소하며, 어떤 조치(배치 해제, 상태를 투입 가능으로 변경)를 하면 표시가 사라지는가? [R2] — 기존 답: 인력 관리자가 확인·해소한다 (legacy REQ-CONTEXT §1.2 "Verification Flow"). 해소 조치는 기존 답 없음.
Q12. 프로젝트의 필요 역량은 여러 개(직무·기술·숙련도·인원의 묶음 여러 줄)인가, 하나인가? 필요 인원은 프로젝트 전체 인원인가, 역량별 인원인가? [R3] — 기존 답 없음.
Q13. 대시보드의 "가용 인원 수"는 투입 가능 상태이면서 오늘 가용률이 0%보다 큰 직원 수인가? [R7] — 기존 답 없음.
Q14. 직원 역할의 사용자는 어느 화면을 쓰는가? 직원 상세(읽기 전용)를 자기 화면으로 쓰는가? [§3 "직원", §6] — 기존 답 없음.
Q15. 역할별로 볼 수 있는 범위는 무엇인가? 직원 역할이 다른 직원, 프로젝트 목록, 대시보드를 볼 수 있는가? [§3] — 기존 답 없음.
Q16. 부서는 화면에서 등록·수정하는가, 시드 데이터로만 제공하는가? [§3 "직원과 부서 정보를 관리한다.", §6] — 기존 답 없음.
Q17. "동일 직원·프로젝트·기간의 중복 배정"은 기간이 완전히 같은 경우만인가, 같은 직원·프로젝트에서 기간이 겹치는 경우 전부인가? [R5] — 기존 답 없음.
Q18. 투입 불가 직원의 기존 배정에서 투입률 수정이나 기간 변경을 허용하는가? [R2 "투입 불가 직원은 신규 프로젝트에 배치할 수 없다.", R4 "투입률 수정"] — 기존 답 없음.
Q19. 모바일에서 지원하는 기능은 어디까지인가? "관리 기능"은 구체적으로 어느 화면·동작인가? [§9 "데스크톱과 모바일에서 핵심 흐름을 사용할 수 있어야 한다.", §13] — 기존 답: 관리 기능을 제외한 모든 기능 (legacy REQ-CONTEXT §1.4 "Mobile Scope"). "관리 기능"의 범위와 기준 화면 너비는 기존 답 없음.
Q20. Java·Spring Boot 버전, 백엔드 빌드 도구(Gradle 또는 Maven), Node 버전과 프런트엔드 패키지 매니저는 무엇인가? [§8] — 기존 답: Java 17 이상, Spring Boot 3.x 이상, SQLite 파일 자동 생성 (legacy foundation.md [C-TECH-01]). 빌드 도구·Node·패키지 매니저는 기존 답 없음.
Q21. 프로젝트 기간을 줄여 기존 배정이 기간 밖으로 나가면 저장을 막는가? [R3 "시작일·종료일", R5 "프로젝트 기간 밖으로 직원을 배치할 수 없다."] — 기존 답 없음.
Q22. 이 프로젝트는 외부 시스템(외부 API, 공용 서버, 다른 팀 DB) 없이 로컬에서 실행·시연하는가? [§8, §10] — 기존 답: SQLite는 동시 사용자가 적어 채택, 저장소 계층으로 DBMS 독립성 유지 (legacy REQ-CONTEXT §1.5 "Database Strategy"). 시연 환경과 외부 시스템 여부는 기존 답 없음.
Q23. 데모 시드 데이터는 몇 건인가(부서, 직원, 프로젝트, 배치)? [§9] — 기존 답: 부서 3, 직원 20, 프로젝트 5 (legacy REQ-CONTEXT §1.5 "Seed Data Volume"). 배치 수와 검증 시나리오(§7)용 데이터 포함 여부는 기존 답 없음.
