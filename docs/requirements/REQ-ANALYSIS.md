## 2. 데이터와 관계

| 엔터티 | 속성 | 원문 |
|---|---|---|
| 부서 | 이름 (그 밖의 속성은 원문에 없음) | "직원과 부서 정보를 관리한다." (§3), "부서" (R1) |
| 직원 | 이름, 부서, 직무, 경력, 투입 가능 상태, 투입 불가 사유, 투입 불가 종료 예정일 | R1 목록 |
| 직원 기술 | 기술 스택, 기술별 숙련도 | "기술 스택", "기술별 숙련도" (R1) |
| 프로젝트 | 프로젝트명, 설명, 시작일·종료일, 프로젝트 상태 | R3 목록 |
| 프로젝트 필요 역량 | 필요 직무, 필요 기술, 필요 숙련도, 필요 인원 | R3 목록 |
| 배치 | 직원, 프로젝트, 투입 시작일, 투입 종료일, 투입률 | "배치 정보:" (R4) |

관계:

- 부서 1 — N 직원 ("부서" R1).
- 직원 1 — N 직원 기술 ("기술 스택", "기술별 숙련도" R1).
- 프로젝트 1 — N 필요 역량. 필요 역량이 하나인지 여럿인지, 필요 인원이 프로젝트 전체인지 역량별인지는 원문에 없다 (Q12).
- 직원 N — M 프로젝트, 배치를 통해 연결 ("참여 프로젝트", "프로젝트별 투입률" R1; "배치된 직원", "직원별 투입률" R3).
- 계산값: 직원의 참여 프로젝트·프로젝트별 투입률·현재 가용률은 배치에서 계산한다 ("현재 가용률" R1, R5).
- 사용자와 역할: 원문은 역할 세 가지를 정의하지만 사용자 계정과 직원의 관계는 정의하지 않는다 (§3; Q6, Q7).

## 3. 업무 규칙

상태:

- 직원 상태는 `투입 가능`, `투입 불가` 중 하나 (R2).
- `확인 필요`는 저장되는 상태가 아니라 표시: 투입 불가이면서 기존 배정이 있는 직원 ("기존 배정이 있는 투입 불가 직원은 `확인 필요`로 표시한다." R2).
- 프로젝트 상태 값은 원문에 없다 ("프로젝트 상태" R3; Q3).

전이:

- 투입 불가 → 투입 가능 자동 전이 없음 ("종료 예정일이 지나도 상태를 자동으로 변경하지 않는다." R2).
- 투입 불가로 바꿔도 기존 배정 유지 ("기존 프로젝트 배정은 상태 변경 시 자동 삭제하지 않는다." R2).

계산:

- 가용률 = 100% − 겹치는 기간의 투입률 합계 (R5).
- 기간이 겹치는 배정만 합산 ("기간이 겹치는 배정만 투입률을 합산한다." R5).
- 종료된 프로젝트는 현재 가용률에서 제외 ("종료된 프로젝트는 현재 가용률 계산에서 제외한다." R5). "종료"의 기준과 "현재"의 기준일은 원문에 없다 (Q9).
- 배치 해제 시 재계산 ("배치를 해제하면 가용률을 다시 계산한다." R5).

검증 (저장 차단):

- 같은 기간 총투입률 ≤ 100% ("같은 기간의 총투입률은 100%를 초과할 수 없다.", "신규 배치 후 100%를 넘으면 저장을 차단한다." R5).
- 배치 기간 ⊆ 프로젝트 기간 ("프로젝트 기간 밖으로 직원을 배치할 수 없다." R5).
- 동일 직원·프로젝트·기간 중복 금지 ("동일 직원·프로젝트·기간의 중복 배정을 허용하지 않는다." R5). "동일 기간"이 완전히 같은 기간인지 겹치는 기간인지는 원문에 없다 (Q17).
- 신규 배치 조건: 상태 투입 가능 AND 대상 기간 가용률 > 0% AND 배치 후 총투입률 ≤ 100% (R6). 기간 중 날마다 가용률이 다를 때 어느 값을 쓰는지는 원문에 없다 (Q8).

권한:

- 상태 변경은 인력 관리자만 ("인력 관리자만 상태를 변경할 수 있다." R2).
- 직원·부서·역량 관리는 인력 관리자 ("직원과 부서 정보를 관리한다.", "직원의 기술·숙련도·경력을 관리한다." §3).
- 프로젝트·필요 역량 관리, 배치·해제는 프로젝트 관리자 ("프로젝트와 필요 역량을 관리한다.", "프로젝트에 직원을 배치하거나 해제한다." §3; "프로젝트 관리자는 프로젝트에 직원을 배치할 수 있다." R4).
- 직원은 자신의 프로필·역량·프로젝트·투입률만 확인 ("자신의 프로필과 역량을 확인한다.", "자신의 프로젝트와 투입률을 확인한다." §3). 다른 직원·대시보드 접근 여부는 원문에 없다 (Q15).

## 4. 화면과 사용자의 일

| 화면 | 사용자 | 하는 일 | 원문 |
|---|---|---|---|
| 1. 통합 대시보드 | 관리자 (직원 접근은 Q15) | 인원·프로젝트·투입률 현황을 보고, 부족 프로젝트·확인 필요 배치에서 상세로 이동 | R7, §6 |
| 2. 직원 목록 | 인력 관리자, 프로젝트 관리자 | 이름 검색, 부서·기술·상태·가용률 필터로 직원 찾기 | R1, §6 |
| 3. 직원 상세·등록·수정 | 인력 관리자 (수정), 프로젝트 관리자·직원 (조회) | 직원 정보·역량·상태 관리, 배치 현황 확인 | R1, R2, R4, §6 |
| 4. 프로젝트 목록 | 프로젝트 관리자 | 상태별 필터로 프로젝트 찾기 | R3, §6 |
| 5. 프로젝트 상세·등록·수정 | 프로젝트 관리자 | 프로젝트·필요 역량 관리, 인력 현황·배치 인력 확인 | R3, R4, §6 |
| 6. 프로젝트 인력 배치 | 프로젝트 관리자 | 가용 직원 확인, 기간·투입률 지정해 배치, 투입률 수정, 해제 | R4, R5, R6, §6 |

화면 목록에 없는 것: 부서 관리 화면 (Q16), 직원 본인 화면 (Q14), 로그인·역할 전환 (Q6).

## 6. 스택과 제약

| 구성 요소 | 이 프로젝트에서 만들고 실행 | 변경 가능 | 원문 |
|---|---|---|---|
| 프런트엔드 (React, TypeScript) | 예 | 예 | "프런트엔드: React, TypeScript" (§8) |
| 백엔드/API (Java, Spring Boot, REST) | 예 | 예 | "백엔드/API: Java, Spring Boot", "통신: REST API" (§8) |
| 데이터베이스 (SQLite 파일) | 예 (프로젝트가 만드는 로컬 파일) | 예 | "데이터베이스: SQLite" (§8) |
| 외부 시스템 | 원문에 없음 | — | — |

- 외부 시스템(외부 API, 공용 서버, 다른 팀의 DB)은 원문에 없다. 따라서 환경별 주소, 소유자, 허용 작업, 설정·자격 증명 준비 방식은 해당 없음으로 본다. 다른 시스템을 쓰지 않는다는 확인은 Q22.
- 런타임 버전, 빌드 도구(Gradle/Maven), 프런트엔드 패키지 매니저는 원문에 없다 (Q20).
- 실행·시연 환경(로컬 한 대 또는 서버)은 원문에 없다 (Q22).
- 제약: 개발 기간 2일 ("개발 기간: 2일" §1), 개발 방식 NEXI (§1, §12).
- 팀 제약: "검토자는 자신이 직접 구현한 코드를 승인하지 않는다." (§11)
