### 고침 — 지적 1(P1): `ECONNREFUSED`가 아닌 오류·타임아웃도 "비어 있음"으로 처리함

1차 고침에서 `node`가 깨지는 경우는 거부로 바꿨지만, 소켓의 `error` 이벤트(연결 거부 포함 모든
오류 — 예: EPERM/EACCES/ENOTFOUND)와 2초 타임아웃을 전부 "비어 있음"으로 묶어서, 실제로 백엔드가
떠 있어도 연결 검사가 권한 등으로 막히거나 응답 없이 멈추면 삭제가 진행될 수 있었다. `err.code`를
확인해 **정확히 `ECONNREFUSED`일 때만 "비어 있음"**으로 보고, 그 외 모든 오류와 타임아웃은 "확인
불가 → 거부"로 바꿨다(`scripts/reset-db.sh`, `scripts/run.sh` 둘 다).

로직을 독립적으로(스크립트 밖에서) 직접 확인:

```
$ node -e '...ECONNREFUSED 분기...' 39999 localhost   # 실제로 비어 있는 포트
err.code=ECONNREFUSED
exit=55   (비어 있음 — 올바름)

$ node -e '...같은 로직...' 80 203.0.113.1   # 응답이 없는 주소(RFC 5737 TEST-NET, 보통 null-routed)
(2초 뒤) exit=66   (확인 불가 — 올바름, 이전 설계라면 "비어 있음"으로 잘못 처리했을 경우)
```

스크립트 레벨에서 "확인 불가(66)"가 거부로 이어지는지도 확인(가짜 `node`로 66을 내도록 해, 대상 경로가
없어 symlink 해석을 타지 않게 함):

```
$ PATH=<node가 66을 내는 가짜 bin>:$PATH RESET_DB_PATH=.nexi-tmp/t57-check/app.db BACKEND_PORT=28080 make reset-db
reset-db: 포트 28080 상태를 확인할 수 없습니다 — 아무것도 지우지 않았습니다
exit=1(스크립트)
```
