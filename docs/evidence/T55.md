## 기준선 (regression, 스텁 단계에서 처음부터 통과한 단언)

- 기준 7 "calls the global fetch once with the same url and the same init…": 지금도 그대로 넘기는 스텁이라 참이다. 구현 뒤에도 같은 인자 보존을 지키는 회귀 검사.

- 기준 4 `from`이 안전하지 않은 값 6종과 "applies the role guard to the place it returns to"(직원 계정 → `/me`): 지금은 `from`을 읽지 않아 항상 `homePath`로 간다. 구현 뒤 `from`을 읽게 되므로, 이 단언들이 구현 뒤에도 `homePath`를 지키는 회귀 검사다.

## REVISE 수정 (리뷰 272fdd9, P2: `Request` 입력의 `signal`)

리뷰 지적: `apiFetch`는 `Request` 입력을 받지만 취소 여부를 `init.signal`에서만 읽는다. 새 검사 `client.test.ts` "does not take the 401 of a cancelled Request for an expired session, and lets init.signal override the signal of the Request"를 먼저 썼다.

- 레드 (기능 코드 `903a9eb`/`4fa9ff7`의 `client.ts` 그대로): `cd frontend && npx vitest run src/api/client.test.ts` — exit 1, `Tests 1 failed | 7 passed (8)`, 실패한 단언 `expected "vi.fn()" to not be called at all, but actually been called 1 times`(취소된 `Request`의 401이 만료 처리기를 부름). 종류: new.
- 수정: `frontend/src/api/client.ts`가 `init.signal ?? (input instanceof Request ? input.signal : undefined)`로 취소 여부를 읽는다(`fetch`처럼 `init.signal`이 `Request`의 signal보다 우선). 호출부 변경 없음.
- 그린 (snapshot `71b369b7193353584d3c83545a2836057c301913`, base `d86d305`): 새 검사 포함 전부 exit 0.
