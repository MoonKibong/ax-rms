## 시드 값 교차 확인

계약서의 구체적 수치(부서 8명, Java 2명, UNAVAILABLE 1명, 가용률 60 이상 15명, 박소영 현재 가용률 40 등)는
`SeedRunner.java`를 직접 읽어 재계산했고, 격리된 임시 DB(저장소 밖, `nexi-isolated.sh --file DB_PATH=...`)에서
실제 시드를 한 번 실행해 부서·기술·배치-프로젝트 매핑의 구조를 대조했다(계약 작성 때 수행, 날짜 의존 수치는
시드 소스의 오프셋을 `FIXED_TODAY=2026-06-15` 기준으로 재계산). `EmployeeApiTest`는 이름으로 직원·부서를
찾아 쓰고, id를 하드코딩하지 않는다.

## 테스트 실행 순서와 격리

`EmployeeApiTest`는 하나의 시드된 DB(클래스당 임시 SQLite, T#5/T#7과 같은 방식)를 모든 테스트 메서드가
공유한다. 목록 필터(기준 1–3)가 세는 건수가 등록·상태 변경(기준 8, 10–12)의 변경과 겹치지 않도록
`@TestMethodOrder`로 순서를 고정했다: 읽기 전용 검사(1–7)를 먼저, 그 다음 등록·수정·상태 변경을 순서대로
실행한다. 상태를 바꾸는 테스트는 서로 다른 직원(오승현, 박소영, 정하늘)을 쓰고, 상태 검증·복귀 테스트(기준
12)는 한 테스트 안에서 자기 변경을 스스로 되돌려 다른 테스트에 영향을 주지 않는다.
