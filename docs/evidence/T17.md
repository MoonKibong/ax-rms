## 알려둘 점 (계약의 `(제안)`을 이렇게 정했다)

- 기간 오류 메시지는 두 날짜 입력 중 **종료일 입력 바로 아래**에 둔다(`aria-describedby`가 가리키는 한 곳). 시작일 입력에는 `aria-invalid`를 두지 않는다. 계약의 "기간 아래"를 이렇게 구현했다.
- 기간이 비었거나 시작일이 종료일보다 늦으면 후보 요청을 보내지 않고 이전 표를 그대로 둔다(배치를 누를 때 서버와 같은 문장을 보인다).
- 수정 모드에서 바뀐 값이 없으면 요청 없이 수정 모드를 끝낸다. 수정 모드를 끝내면 배치 기간은 프로젝트 기간(처음 값)으로 돌아간다.
- 후보 표와 직원 목록 중 하나라도 실패하면 후보 표는 오류 상태(다시 시도가 둘 다 다시 부른다).
- `code`와 `message`를 가진 서버 답은 어떤 코드든 그 메시지를 보인다(리뷰 REVISE 이후). 그것이 없는 오류(네트워크, Spring 기본 본문, 본문 없는 500)는 "저장하지 못했습니다. 잠시 후 다시 시도하세요."이다.
- 인력 관리자만의 계정이 `/projects/:id/assign`을 열면 `/projects/:id`로 돌려보낸다(`ProjectAssignRoute`).

## 리뷰 REVISE(`89544e1`)와 조치

1. `placeAssignmentFailure`(`api/assignments.ts`)가 `ASSIGNMENT_` 접두사만 믿던 것을 고쳤다. `code`와 `message`가 있는 서버 답(`AUTH_REQUIRED`, `AUTH_FORBIDDEN` 등)은 서버 메시지를 그대로 보이고, 알려진 배치 원인은 입력 아래, 나머지는 배치 버튼 위·수정 저장 위·해제 대화상자 안에 둔다. 코드나 메시지가 없는 답(네트워크 오류, Spring 기본 본문, 본문 없는 500)만 "저장하지 못했습니다"이다. 검사: Vitest `answers of the server that are not about assignments` 4개(401·403 배치, 수정 저장, 해제 대화상자).
2. 수정 중인 배치를 해제하면 해제가 성공할 때 수정 모드를 끝낸다(`ProjectAssignPage.tsx`의 `onReleased`). 다른 배치를 해제하면 수정 모드는 그대로다. 검사: Vitest `ends the edit mode when the assignment being edited is released…`, `keeps the edit mode when another assignment is released`.
3. 스크린샷 스펙의 제목 확인: `support/assign.ts`의 `expectHeading`에 h1 `toBeVisible()`을 더하고, 해제 화면은 대화상자 제목 "배치 해제"의 `toBeVisible()`도 단언한다(`e2e/screens/T17.spec.ts`). 수정 뒤 `make screenshots T=17`을 다시 돌렸고 PNG 6장은 이전과 바이트가 같다(`git status`에 변경 없음).
