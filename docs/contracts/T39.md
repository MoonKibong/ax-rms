### 등록 `/employees/new`, 수정 `/employees/:id/edit` (BRIEF 6.4 폼)

- 제목(h1): "직원 등록", "직원 수정".
- 불러오기: 등록은 `GET /api/departments`, 수정은 그것과 `GET /api/employees/{id}`를 함께 부른다. 그동안 `Spinner`와 "불러오는 중…",
  `aria-busy="true"`. 하나라도 실패하면 StateMessage `error`(API `message`가 있으면 그 글자, 404는 "직원을 찾을 수 없습니다.")와
  "다시 시도"이고, 다시 시도는 그 화면의 요청을 모두 다시 보낸다.
- `form`은 `noValidate`다(브라우저 말풍선 대신 BRIEF 3.2의 오류 표시). 한 열, 최대 너비 560px, 필드 사이 `--space-4` (제안). 필드
  순서(D2):
  1. 이름 `*` — `TextField`.
  2. 부서 `*` — `SelectField`: "선택하세요"(빈 값), 그 뒤 부서 응답 순서(글자 `name`, 값 `id`). 수정은 그 직원의 부서가 골라져 있다.
  3. 직무 `*` — `TextField`.
  4. 기술 — `fieldset`(legend "기술", sm/600). 줄마다 `role="group"` `aria-label="기술 N"`(N은 1부터)이고, 그 안에 `TextField` "기술
     이름", `SelectField` "숙련도"("선택하세요", `초급`, `중급`, `고급`, D11), secondary "삭제"(접근 이름 "기술 N 삭제"). 줄은
     `1fr 140px auto`, 간격 `--space-2` (제안). 줄 아래 secondary "기술 추가"는 빈 줄을 끝에 더하고 그 줄의 기술 이름에 포커스를 둔다.
     수정은 API 순서대로 줄이 차 있다. 기술이 없으면 줄 없이 "기술 추가"만 있다.
  5. 경력(년) `*` — `TextField` `type="number"`, `min=0`, `step=1`, `inputMode="numeric"` (D12).
- 버튼 줄: secondary "취소", primary "저장", 간격 `--space-2` (제안).
- 상태 필드는 폼에 없다. 상태는 대화상자로만 바꾼다(D6, #8).
- **요청**: 등록 `POST /api/employees`, 수정 `PUT /api/employees/{id}`, `Content-Type: application/json`, 본문은 정확히
  `{"name", "departmentId", "jobTitle", "careerYears", "skills": [{"skillName", "proficiencyLevel"}]}`.
  - `name`, `jobTitle`, `skillName`은 앞뒤 공백을 지운다 (제안). `departmentId`는 고른 id 숫자, 안 골랐으면 `null`.
    `proficiencyLevel`은 고른 값(`BEGINNER`·`INTERMEDIATE`·`ADVANCED`), 안 골랐으면 `""`. 기술 줄은 화면 순서대로 모두 보낸다(빈
    줄도 보내 서버가 판단한다).
  - `careerYears`: 빈 칸이면 `null`. `^-?[0-9]+$`이고 −2147483648–2147483647이면 그 정수. 그 밖(`1.5`, `1e2`, `99999999999`)이면
    요청을 보내지 않고 경력 아래에 "경력은 정수로 입력하세요."를 보인다 (제안). 음수는 서버가 판단한다.
- **서버 오류의 자리 (D33)**: 메시지는 API `message` 그대로, TextField 오류 규칙(BRIEF 3.2)으로 보인다.

  | 응답 | 자리 |
  |---|---|
  | 400 `EMPLOYEE_NAME_REQUIRED` | 이름 아래 |
  | 400 `EMPLOYEE_DEPARTMENT_NOT_FOUND` | 부서 아래 |
  | 400 `EMPLOYEE_JOB_TITLE_REQUIRED` | 직무 아래 |
  | 400 `EMPLOYEE_CAREER_YEARS_INVALID` | 경력 아래 |
  | 400 `EMPLOYEE_SKILL_INVALID`, `EMPLOYEE_SKILL_DUPLICATE` | 기술 줄 아래, "기술 추가" 위(같은 글자·아이콘). `fieldset`의 `aria-describedby`가 가리킨다 |
  | 그 밖의 `code`, 401·403·404·5xx, `code` 없는 응답, 네트워크 오류 | 버튼 줄 바로 위 폼 메시지(`role="alert"`, danger, 경고 아이콘): API `message`, 없으면 "저장하지 못했습니다. 잠시 후 다시 시도하세요." (제안) |

  서버가 한 번에 하나를 주므로 화면도 하나를 보인다. 다시 저장하면 앞 메시지를 지운다.
- 저장 중에는 "저장"이 loading이고, 다시 누르거나 Enter를 눌러도 요청을 더 보내지 않는다.
- 성공: 등록 201이면 응답 `id`의 `/employees/{id}`로, 수정 200이면 `/employees/{id}`로 간다(`replace`). 상세는 그 주소에서 다시
  불러온다(D36).
- 취소: 등록은 `/employees`로, 수정은 `/employees/{id}`로 간다. 요청을 보내지 않는다.

### 데스크톱 이용 안내 (좁은 구간의 폼 주소, D29)

- 1023px 이하에서 인력 관리자가 `/employees/new`나 `/employees/:id/edit`를 열면 제목(h1) 아래에 폼 대신 안내 블록만 보인다. 역할에
  따른 이동(위 표)이 먼저다.
- 안내 블록 (제안): StateMessage 블록과 같은 모양(가운데 정렬, 패딩 `--space-6` `--space-4`, surface, 1px border, `--radius-md`),
  아이콘 없음, `role="status"`. 제목 "데스크톱에서 이용해 주세요"(md/600, text), 설명 "직원 등록·수정은 너비 1024px 이상 화면에서 할 수
  있습니다."(sm, text-muted), 그 아래 secondary 버튼 모양의 링크 "직원 목록으로"(등록, → `/employees`) 또는 "직원 상세로"(수정, →
  `/employees/:id`).
- 폼 영역(불러오는 중·오류 포함)은 1023px 이하에서 `display: none`이라 보이지 않고 포커스를 받지 않는다. 1024px 이상에서는 안내
  블록이 `display: none`이다. 같은 폼을 숨길 뿐이라, 창을 줄였다 넓혀도 입력한 값이 남는다 (제안).

### 상태 변경 대화상자 (D6, D21, BRIEF 6.4)

- "상태 변경"을 누르면 `Dialog`가 열린다. 제목 "상태 변경".
- 필드: 상태 `*` `SelectField`("투입 가능" `AVAILABLE`, "투입 불가" `UNAVAILABLE`, 처음 값은 지금 상태). "투입 불가"일 때만 사유 `*`
  `TextField`(처음 값은 지금 사유 또는 빈 칸)와 종료 예정일 `TextField` `type="date"`(지금 값 또는 빈 칸)를 그린다.
- 버튼: secondary "취소", primary "저장".
- 요청 `PATCH /api/employees/{id}/status`, 본문은 정확히: 투입 불가면 `{"availabilityStatus": "UNAVAILABLE", "unavailableReason":
  <앞뒤 공백을 지운 사유>, "unavailableUntil": <"YYYY-MM-DD", 빈 칸이면 null>}`, 투입 가능이면 `{"availabilityStatus": "AVAILABLE",
  "unavailableReason": null, "unavailableUntil": null}`.
- 오류: 400 `EMPLOYEE_REASON_REQUIRED`는 사유 아래, 400 `EMPLOYEE_STATUS_INVALID`는 상태 아래, 그 밖은 대화상자 버튼 줄 위 메시지(폼과
  같은 규칙).
- 저장 중: "저장" loading, "취소" `disabled`, Esc로 닫히지 않는다 (제안).
- 성공(200): 대화상자가 닫히고 상세가 응답 본문(서버가 다시 읽은 상세)으로 바뀐다: 배지, 사유, 종료 예정일, 확인 필요, 가용률. 배치는
  그대로다(D6). 포커스는 "상태 변경"으로 돌아간다.
- 취소·Esc: 요청 없이 닫고 입력을 버린다. 포커스는 "상태 변경"으로 돌아간다. 바탕을 눌러도 닫히지 않는다 (제안).

### 컴포넌트

- **`SelectField` 오류·필수** (BRIEF 3.2 "선택 상자는 TextField와 같은 … 오류 규칙"): 속성 `error`, `required`를 더한다. `error`가 있으면
  테두리 danger, 메시지는 `select` 바로 아래 4px, 왼쪽 끝 맞춤, sm/400 danger와 16px 경고 아이콘, `select`에 `aria-invalid="true"`와
  메시지를 가리키는 `aria-describedby`. `required`면 라벨 뒤 `*`(danger, `aria-hidden`)와 `select`의 `required`. 둘 다 없으면 #13과 같다.
- **`Dialog`** (BRIEF 3.6 "화면 안 대화상자", #17이 배치 해제 확인에 쓴다): 속성은 제목, `onClose`, 닫기 허용 여부(저장 중 Esc 막기),
  내용. 그려져 있는 동안 열려 있다.
  - `role="dialog"`, `aria-modal="true"`, 제목(h2, lg/600)을 가리키는 `aria-labelledby`.
  - 열리면 안의 첫 포커스 가능한 요소에 포커스, Tab·Shift+Tab은 대화상자 안을 돈다(바깥 본문으로 나가지 않는다), Esc는 `onClose`.
    닫히면 열기 전에 포커스가 있던 요소로 포커스가 돌아간다.
  - 모양 (제안): 너비 `min(480px, 100vw − 32px)`, 화면 가운데(고정), surface, `--radius-md`, `--shadow-md`, 패딩 `--space-6`. 버튼
    줄은 끝 정렬, 간격 `--space-2`. 바탕은 뷰포트 전체를 `color-mix(in srgb, var(--color-text) 40%, transparent)`로 덮는다(새 토큰
    없음).
  - 만드는 법(`<dialog>`의 `showModal()` 등)은 정하지 않는다. 위 동작이 Vitest(jsdom)와 Chromium에서 같아야 한다.

## 실행별 임시 DB (e2e 저장 검사)

공유 e2e DB(`backend/data/e2e.db`)는 한 번 만든 뒤 계속 쓰는 파일이다. 그래서 그 DB로 도는 스펙(`e2e` 프로젝트, 스크린샷)은 직원
쓰기를 서버에 보내지 않는다: 화면이 보내는 `POST`·`PUT`·`PATCH /api/employees…`는 `page.route`로 받아 고정 응답으로 끝내고,
`page.request`로 쓰기를 보내지 않는다. 실제로 저장하고 다시 읽는 검사는 실행마다 새로 만들고 끝나면 지우는 DB에서만 한다.

- `scripts/e2e-servers.sh [--fresh-db] -- <명령>`.
  - 선택이 없으면 지금과 같다(DB `backend/data/e2e.db`, 명령 환경에 `E2E_DB`를 두지 않는다). T#4 기준 11의 동작은 그대로다.
  - `--fresh-db`면 백엔드 DB가 `<저장소>/.nexi-tmp/e2e-write.db`다. 순서:
    1. 출력 경로 확인에 그 DB 파일과 `-journal`·`-wal`·`-shm`을 더한다. 하나라도 심볼릭 링크이거나, 일반 파일이 아니거나, 저장소
       밖이면 아무것도 쓰거나 지우거나 띄우지 않고 2로 끝난다(출력 `출력 경로 거부`).
    2. 포트 확인. 쓰이고 있으면 아무 파일도 지우지 않고 끝난다(지금과 같은 `포트 … 사용 중`).
    3. 그 네 파일을 지운다 → 빌드 → 백엔드를 `--file DB_PATH=.nexi-tmp/e2e-write.db`로 띄운다(빈 DB라 시더가 D31 시드를 넣는다,
       D38) → 명령을 `E2E_DB=fresh` 환경으로 실행한다.
    4. 끝나면(성공·실패·중단 모두) 서버를 내린 뒤 그 네 파일을 지운다. 1에서 거부했으면 지우지 않는다.
  - 포트(18080, 14173), 프런트엔드 빌드, 서버 기록 파일은 지금과 같다. 두 실행은 포트 확인 때문에 동시에 돌 수 없다.
- Playwright: 새 프로젝트 `e2e-write`(`testMatch: 'write/*.spec.ts'`). 기존 `e2e` 프로젝트는 `**/write/**`도 제외한다. `screens`는
  그대로다.
- `frontend/package.json`: `e2e:write`는 `playwright test --project=e2e-write`. `test:e2e`는 지금의 공유 DB 단계 다음에
  `bash ../scripts/e2e-servers.sh --fresh-db -- npm run e2e:write`를 `&&`로 잇는다. 그래서 `make test`가 두 단계를 모두 돈다.
- `write/` 스펙은 맨 먼저 `process.env.E2E_DB`가 `fresh`인지 보고, 아니면 요청을 하나도 보내지 않고 메시지
  `write 스펙은 scripts/e2e-servers.sh --fresh-db로만 실행합니다 (E2E_DB=fresh 아님)`로 실패한다 (제안: 글자).
- README "검사 격리" 표에 줄을 더한다: "e2e 저장 검사 DB 파일 | `<root>/.nexi-tmp/e2e-write.db`, 실행마다 새로 만들고 끝나면 지운다 |
  `scripts/e2e-servers.sh --fresh-db`가 `--file DB_PATH=.nexi-tmp/e2e-write.db`로 띄운다".
