# T#57 변경: `make run`과 시연 DB 재생성

## 산출물

`make run` 한 줄이 Node 버전·포트를 확인한 뒤 백엔드(`127.0.0.1`로만 열림)와 프런트엔드를 함께 띄우고 Ctrl-C
하나로 함께 내리며, `make reset-db`가 시연 DB(와 그 WAL·SHM·journal 파일)를 지워 다음 실행이 "오늘" 기준으로
§7 시나리오를 다시 심게 한다.

## 수용 기준

1. **`server.address` 기본값 127.0.0.1 (B#15).** `application.yml`에
   `server.address: ${SERVER_ADDRESS:127.0.0.1}`를 추가한다(`DB_PATH`와 같은 자리표시자 방식). 환경변수
   `SERVER_ADDRESS`를 주지 않고 백엔드를 실행하면 `127.0.0.1`에만 열린다(모든 네트워크 아님). 환경변수로
   재정의할 수 있다(예: 컨테이너·CI 안에서 `0.0.0.0`이 필요해지면).
   - 확인: `com.ax.rms.config.ServerAddressConfigTest`(`AbstractDatabaseTest` 확장, `ServerProperties`를
     주입받아 `getAddress()`가 `InetAddress.getByName("127.0.0.1")`인지 확인).
   - 준비: 테스트 클래스만 둔다.
   - 레드: 지금은 `server.address`가 없어 `ServerProperties.getAddress()`가 `null`이다(모든 인터페이스
     바인딩을 뜻함) — `127.0.0.1` 기댓값과 다르다.
2. **`make run` (피드백 8).** 새 스크립트 `scripts/run.sh`와 Makefile `run` 타깃:
   - (a) 설치된 `node -v`가 `.nvmrc`의 값과 다르면, 기대 버전과 "nvm use"로 맞추라는 안내를 출력하고
     그 자리에서 멈춘다(아무 서버도 안 띄움).
   - (b) 백엔드 포트(기본 `8080`, 환경변수 `BACKEND_PORT`로 바꿀 수 있음)·프런트 포트(기본 `5173`,
     `FRONTEND_PORT`)가 하나라도 사용 중이면, 그 포트 번호와 함께 멈춘다(아무 서버도 안 띄움, 그 포트를
     쓰는 프로세스는 건드리지 않음) — `scripts/e2e-servers.sh`의 `port_in_use`를 그대로 재사용한다.
   - (c) 둘 다 비어 있으면, 백엔드(`scripts/nexi-isolated.sh --root "$PWD" --file DB_PATH=backend/data/app.db
     --set SERVER_PORT=$BACKEND_PORT -- ./backend/mvnw -f backend/pom.xml spring-boot:run`, 기준 1의
     127.0.0.1 기본값을 그대로 씀)와 프런트엔드(`npm --prefix frontend run dev -- --port $FRONTEND_PORT`,
     `API_TARGET=http://localhost:$BACKEND_PORT`)를 각자 프로세스 그룹으로 띄우고, 하나의
     SIGINT(Ctrl-C)·SIGTERM으로 둘 다 받아 둘 다 내린다(`scripts/e2e-servers.sh`의 그룹·트랩 패턴 재사용,
     새로 설계하지 않음). 영구 DB(`backend/data/app.db`)를 쓰고 시연이 끝나도 지우지 않는다.
   - 확인: 아래 "검증 명령"의 통합 확인 절차 3개(포트 사용 중일 때 거부, Node 버전 다를 때 거부, 정상
     기동과 Ctrl-C로 둘 다 내려가는지) — e2e-servers.sh 자체도 전용 자동 테스트가 없고 이렇게 직접
     실행해 확인하는 전례(T#4)를 따른다.
   - 준비: 스크립트 뼈대만 둔다(포트·버전 확인 없이 아무것도 안 함).
   - 레드: 지금은 `run` 타깃이 없어 `make run`이 `make: *** No rule to make target 'run'. Stop.`로 끝난다.
3. **`make reset-db` (B#5, 데이터 삭제 — 다른 agent 리뷰 필수).** 새 스크립트 `scripts/reset-db.sh`와
   Makefile `reset-db` 타깃:
   - 대상 경로: 정확히 `${DB_PATH:-backend/data/app.db}`와 그 `-wal`·`-shm`·`-journal` 파일 **만** 지운다
     (존재하는 것만; 없으면 조용히 넘어간다). 다른 DB(`backend/data/e2e.db`, `.nexi-tmp/*`)는 건드리지
     않는다 — 그 파일들은 `scripts/e2e-servers.sh`가 따로 관리한다.
   - 안전 조건(실행 중인 DB 처리): 백엔드 포트(기본 `8080`, `BACKEND_PORT`)가 사용 중이면 "백엔드가
     실행 중인 것으로 보입니다 — 먼저 멈추세요"를 출력하고 **아무 파일도 지우지 않는다**(실행 중인
     프로세스가 쥐고 있는 WAL 파일을 지우면 다음 체크포인트가 깨질 수 있어서).
   - `.gitignore`에 `*.db-wal`·`*.db-shm`·`*.db-journal`을 추가한다(위 "전제"의 확인대로, 지금은
     `*.db`만 있어 이 파일들이 실수로 커밋될 수 있다).
   - 확인: 아래 "검증 명령"의 통합 확인 절차 2개(더미 DB·WAL·journal 파일을 만들어 두고 포트가 비어
     있을 때 셋 다 지워지는지, 포트를 점유해 둔 상태에서는 아무것도 안 지워지는지).
   - 준비: 스크립트 뼈대만 둔다.
   - 레드: 지금은 `reset-db` 타깃이 없어 같은 `make: *** No rule to make target 'reset-db'. Stop.` 오류.
4. **재시드가 "오늘" 기준으로 다시 들어간다(B#5의 근본 목적).** `make reset-db` 뒤 백엔드를 다시 실행하면
   (DB 파일이 없어졌으므로) `SeedRunner`가 그 실행 시점의 "오늘"로 §7 시나리오를 처음부터 다시 심는다.
   - 확인: 새 검사를 추가하지 않는다 — T#5의 `SeedTriggerTest`·`ScenarioDataTest`(이미 `main`에 있고
     "빈 DB로 시작하면 시드가 들어간다"를 고정 `Clock`으로 검증함)가 그대로 이 동작을 보장한다.
     `regression`으로 적는다: 베이스라인(이 태스크 변경 전, `origin/main`)에서 이미 통과한다 —
     `SeedTriggerTest.java`(파일 존재 확인), `./backend/mvnw -f backend/pom.xml test -Dtest=SeedTriggerTest,ScenarioDataTest`
     결과로 확인.
   - 기준 3이 "파일이 실제로 없어진다"를, T#5의 기존 테스트가 "빈 DB면 다시 심는다"를 각각 확인해 둘을
     합치면 "지우면 오늘 기준으로 다시 심어진다"가 보장된다 — 이 기준은 새 코드를 추가하지 않고 그
     합성만 적는다.

## 검증 명령

- 새 검사:
  - `./backend/mvnw -f backend/pom.xml test -Dtest=ServerAddressConfigTest` — 기준 1.
  - `make run`의 통합 확인(기준 2, 작업 폴더에서 직접 실행, 영구 스크립트가 아니라 이 구현 중 red/green만
    기록):
    ```
    # (a) Node 버전 다를 때 거부 — .nvmrc를 임시로 다른 값으로 바꿔 실행
    echo "99.99.99" > .nvmrc.bak && cp .nvmrc .nvmrc.orig && cp .nvmrc.bak .nvmrc
    make run; echo "exit=$?"   # 0이 아니어야 하고, 포트가 그대로 비어 있어야 함
    cp .nvmrc.orig .nvmrc && rm .nvmrc.bak .nvmrc.orig

    # (b) 포트 사용 중일 때 거부 — 더미 리스너로 8080을 점유
    node -e 'require("net").createServer().listen(8080)' &
    dummy=$!
    make run; echo "exit=$?"   # 0이 아니어야 함
    kill $dummy

    # (c) 정상 기동과 Ctrl-C로 함께 내려가는지 — 백그라운드로 띄우고 헬스 확인 후 SIGINT
    make run & runner=$!
    # http://localhost:5173/api/health, http://localhost:8080/api/health 가 응답할 때까지 대기(최대 60초)
    kill -INT $runner
    # 두 포트가 다시 비는지 확인
    ```
  - `make reset-db`의 통합 확인(기준 3):
    ```
    # 더미 DB·WAL·journal 파일 준비
    : > backend/data/app.db; : > backend/data/app.db-wal; : > backend/data/app.db-journal

    # 포트 비었을 때: 지워져야 함
    make reset-db
    ls backend/data/app.db backend/data/app.db-wal backend/data/app.db-journal 2>&1   # 셋 다 없어야 함

    # 다시 더미 파일 준비 + 포트 점유 상태에서: 지워지지 않아야 함
    : > backend/data/app.db
    node -e 'require("net").createServer().listen(8080)' &
    dummy=$!
    make reset-db; echo "exit=$?"
    ls backend/data/app.db   # 그대로 있어야 함
    kill $dummy
    ```
- 회귀 검사: `make build`, `make test`, `make lint` — 작업 전후 모두 통과해야 한다. 특히 `SeedTriggerTest`,
  `ScenarioDataTest`, `SqliteConfigTest`(T#54, `journal_mode`·`busy_timeout` 확인)가 깨지지 않는지 본다

  이미 `localhost`로 접속하므로 영향 없음을 기준 1 구현 뒤 전체 테스트 실행으로 확인한다).

## 하지 않을 일

- 시드 켜기·끄기 설정(B#15가 제안했지만 이슈 본문의 "완료" 정의에는 없다) — 필요해지면 별도 이슈.
- `scripts/nexi-isolated.sh`·`scripts/e2e-servers.sh` 자체를 고치는 일 — `scripts/run.sh`가 그 둘(또는
  그 패턴)을 그대로 불러 쓴다.
- `backend/data/e2e.db`, `.nexi-tmp/*`(e2e·스크린샷 전용 DB) — `make reset-db`는 시연 DB만 다룬다.
- CSRF·로그인 시도 제한(B#16) — 범위 밖, 3.3절 보류.
- 운영 배포용 네트워크 설정(인증서, 리버스 프록시 등) — D40(로컬 시연)만 다룬다.
- `nvm use`를 스크립트가 대신 실행하는 일 — 안내만 하고 실제 전환은 사용자가 한다(nvm 설치 여부·셸 설정에
  스크립트가 의존하게 되는 것을 피한다).
- `SeedRunner.java`의 시드 로직·트리거 조건을 바꾸는 일 — DB 파일을 지워서 그 트리거가 다시 "빈 DB"로
  보게 만들 뿐, 트리거 자체(`count() > 0`이면 건너뜀)는 그대로 둔다.
