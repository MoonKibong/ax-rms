# T#57 변경: `make run`과 시연 DB 재생성

## 산출물

`make run` 한 줄이 Node 버전·포트를 확인한 뒤 백엔드(`127.0.0.1`로만 열림)와 프런트엔드를 함께 띄우고 Ctrl-C
하나로 함께 내리며, `make reset-db`가 시연 DB(와 그 WAL·SHM·journal 파일)를 지워 다음 실행이 "오늘" 기준으로
§7 시나리오를 다시 심게 한다.

## 수용 기준

1. **`server.address` 기본값 127.0.0.1 (B#15).** `application.yml`에
   `server.address: ${SERVER_ADDRESS:127.0.0.1}`를 추가한다(`DB_PATH`와 같은 자리표시자 방식). 환경변수
   `SERVER_ADDRESS`를 주지 않고 백엔드를 실행하면 `127.0.0.1`에만 열린다(모든 네트워크 아님). 환경변수로
   재정의할 수 있다(예: 컨테이너·CI 안에서 `0.0.0.0`이 필요해지면).
   - 확인: `com.ax.rms.config.ServerAddressConfigTest`(`AbstractDatabaseTest` 확장, `ServerProperties`를
     주입받아 `getAddress()`가 `InetAddress.getByName("127.0.0.1")`인지 확인).
   - 준비: 테스트 클래스만 둔다.
   - 레드: 지금은 `server.address`가 없어 `ServerProperties.getAddress()`가 `null`이다(모든 인터페이스
     바인딩을 뜻함) — `127.0.0.1` 기댓값과 다르다.
2. **`make run` (피드백 8).** 새 스크립트 `scripts/run.sh`와 Makefile `run` 타깃:
   - (a) 설치된 `node -v`가 `.nvmrc`의 값과 다르면, 기대 버전과 "nvm use"로 맞추라는 안내를 출력하고
     그 자리에서 멈춘다(아무 서버도 안 띄움). **`.nvmrc`는 읽기만 하고 절대 쓰지 않는다** — 스크립트는
     항상 저장소의 `.nvmrc` 값을 "기대 버전"으로 쓰고, 실제 설치된 버전만 `PATH`의 `node` 바이너리로
     판단한다(테스트가 바꾸는 건 `.nvmrc`가 아니라 `PATH`의 어떤 `node`가 먼저 잡히는지뿐이다 — 아래
     "검증 명령").
   - (b) 백엔드 포트(기본 `8080`, 환경변수 `BACKEND_PORT`로 바꿀 수 있음)·프런트 포트(기본 `5173`,
     `FRONTEND_PORT`)가 하나라도 사용 중이면, 그 포트 번호와 함께 멈춘다(아무 서버도 안 띄움, 그 포트를
     쓰는 프로세스는 건드리지 않음) — `scripts/e2e-servers.sh`의 `port_in_use`를 그대로 재사용한다.
   - (c) 둘 다 비어 있으면, 백엔드(`scripts/nexi-isolated.sh --root "$PWD" --file DB_PATH=backend/data/app.db
     --set SERVER_PORT=$BACKEND_PORT -- ./backend/mvnw -f backend/pom.xml spring-boot:run`, 기준 1의
     127.0.0.1 기본값을 그대로 씀)와 프런트엔드(`npm --prefix frontend run dev -- --port $FRONTEND_PORT`,
     `API_TARGET=http://localhost:$BACKEND_PORT`)를 각자 프로세스 그룹으로 띄우고, 하나의
     SIGINT(Ctrl-C)·SIGTERM으로 둘 다 받아 둘 다 내린다(`scripts/e2e-servers.sh`의 그룹·트랩 패턴 재사용,
     새로 설계하지 않음). 영구 DB(`backend/data/app.db`)를 쓰고 시연이 끝나도 지우지 않는다.
   - README의 "실행" 절에 `make run` 한 줄 사용법과 `BACKEND_PORT`/`FRONTEND_PORT`로 포트를 바꾸는 법을
     적는다(피드백 8이 지적한 "두 줄·터미널 두 개" 절차를 이 한 줄로 대체한다고 적음).
   - 확인: 아래 "검증 명령"의 통합 확인 절차 3개 — **전부 실제 기본 포트(8080/5173)가 아니라
     `BACKEND_PORT`/`FRONTEND_PORT`로 지정한, 평소 안 쓰는 포트(예: `28080`/`25173`)에서 돈다**(이
     컴퓨터의 다른 개발 서버와 겹치지 않게). (포트 사용 중일 때 거부, `PATH` 앞단의 가짜 `node`로 버전
     다를 때 거부, 정상 기동과 Ctrl-C로 둘 다 내려가는지) — e2e-servers.sh 자체도 전용 자동 테스트가
     없고 이렇게 직접 실행해 확인하는 전례(T#4)를 따른다.
   - 준비: 스크립트 뼈대만 둔다(포트·버전 확인 없이 아무것도 안 함).
   - 레드: 지금은 `run` 타깃이 없어 `make run`이 `make: *** No rule to make target 'run'. Stop.`로 끝난다.
3. **`make reset-db` (B#5, 데이터 삭제 — 다른 agent 리뷰 필수).** 새 스크립트 `scripts/reset-db.sh`와
   Makefile `reset-db` 타깃:
   - **인자로만 대상을 받는다 — 셸에 남은 `DB_PATH`(앱이 연결에 쓰는 환경변수)는 무시한다.**
     `scripts/reset-db.sh --db <경로> --port <포트>`로 호출하고, `--db`를 안 주면 기본값
     `backend/data/app.db`다. Makefile `reset-db` 타깃은
     `scripts/reset-db.sh --db "$${RESET_DB_PATH:-backend/data/app.db}" --port "$${BACKEND_PORT:-8080}"`로
     부른다(앱의 `DB_PATH`와 겹치지 않는, 이 스크립트만의 변수 `RESET_DB_PATH`를 새로 둔다 — 사용자
     셸에 다른 이유로 남아 있을 수 있는 `DB_PATH`가 삭제 대상에 영향을 주지 않게 하는 결정이다).
   - **경로 제한.** `--db`로 받은 경로를 저장소 루트 기준 실제 경로(symlink 해석 포함)로 바꾼 뒤, 그
     결과가 저장소 루트 **안**이 아니면("`..`"로 밖을 가리키거나 절대 경로가 루트 밖이면) 아무것도
     지우지 않고 거부한다("경로가 저장소 밖을 가리켜 거부" 메시지).
   - 대상 경로: 그 경로(저장소 안으로 확인된)와 그 `-wal`·`-shm`·`-journal` 파일 **만** 지운다(존재하는
     것만; 없으면 조용히 넘어간다). 다른 DB(`backend/data/e2e.db`, `.nexi-tmp/*`)는 건드리지 않는다 — 그
     파일들은 `scripts/e2e-servers.sh`가 따로 관리하고 `--db`로 그 경로를 주지 않는 한 손대지 않는다.
   - 안전 조건(실행 중인 DB 처리): `--port`(기본 `8080`)가 사용 중이면 "백엔드가 실행 중인 것으로
     보입니다 — 먼저 멈추세요"를 출력하고 **아무 파일도 지우지 않는다**(실행 중인 프로세스가 쥐고 있는
     WAL 파일을 지우면 다음 체크포인트가 깨질 수 있어서).
   - `.gitignore`에 `*.db-wal`·`*.db-shm`·`*.db-journal`을 추가한다(위 "전제"의 확인대로, 지금은
     `*.db`만 있어 이 파일들이 실수로 커밋될 수 있다).
   - README의 "DB 준비" 절에 `make reset-db`의 사용법(무엇을 지우는지 — 시연 DB와 WAL/SHM/journal만,
     `e2e.db`는 안 건드림 —, 백엔드가 떠 있으면 거부됨, `RESET_DB_PATH`/`BACKEND_PORT`로 바꾸는 법)을
     적는다.
   - 확인: 아래 "검증 명령"의 통합 확인 절차 3개 — (i) **격리된 임시 경로**(`.nexi-tmp/t57-check/`
     아래, `.gitignore`가 이미 덮는 폴더)에 더미 DB·WAL·journal을 만들어 `--db`로 그 경로를 줘서 지워지는지
     확인하고, 그 **전후로 실제 `backend/data/app.db`의 체크섬이 그대로인지**(`cksum`) 함께 보여준다(이
     확인이 실제 시연 DB를 건드리지 않는다는 증거); (ii) 그 임시 경로를 점유 중인(가짜 포트 점유) 상태로
     실행해 아무것도 안 지워지는지; (iii) 저장소 밖 경로(예: `/tmp/outside.db`나 `../outside.db`)를
     `--db`로 주면 거부되고 그 경로의 파일이 그대로인지.
   - 준비: 스크립트 뼈대만 둔다.
   - 레드: 지금은 `reset-db` 타깃이 없어 같은 `make: *** No rule to make target 'reset-db'. Stop.` 오류.
4. **재시드가 "오늘" 기준으로 다시 들어간다(B#5의 근본 목적).** `make reset-db` 뒤 백엔드를 다시 실행하면
   (DB 파일이 없어졌으므로) `SeedRunner`가 그 실행 시점의 "오늘"로 §7 시나리오를 처음부터 다시 심는다.
   - 확인: 새 검사를 추가하지 않는다 — T#5의 `SeedTriggerTest`·`ScenarioDataTest`(이미 `main`에 있고
     "빈 DB로 시작하면 시드가 들어간다"를 고정 `Clock`으로 검증함)가 그대로 이 동작을 보장한다.
     `regression`으로 적는다: 베이스라인(이 태스크 변경 전, `origin/main`)에서 이미 통과한다 —
     `SeedTriggerTest.java`(파일 존재 확인), `./backend/mvnw -f backend/pom.xml test -Dtest=SeedTriggerTest,ScenarioDataTest`
     결과로 확인.
   - 기준 3이 "파일이 실제로 없어진다"를, T#5의 기존 테스트가 "빈 DB면 다시 심는다"를 각각 확인해 둘을
     합치면 "지우면 오늘 기준으로 다시 심어진다"가 보장된다 — 이 기준은 새 코드를 추가하지 않고 그
     합성만 적는다.

## 검증 명령

모든 아래 절차는 실제 시연 DB(`backend/data/app.db`)나 기본 포트(8080/5173)를 건드리지 않는다 — 전부
`.nexi-tmp/`(이미 `.gitignore`가 덮음) 아래의 임시 경로와, 평소 안 쓰는 포트(예: `28080`/`25173`)만
쓴다. 영구 스크립트가 아니라 이 구현 중 red/green만 기록한다.

- 새 검사:
  - `./backend/mvnw -f backend/pom.xml test -Dtest=ServerAddressConfigTest` — 기준 1.
  - `make run`의 통합 확인(기준 2, 전부 `BACKEND_PORT=28080 FRONTEND_PORT=25173`로 돈다):
    ```
    # (a) PATH 앞단에 가짜 node를 둬서 버전 불일치를 만듦 — .nvmrc는 전혀 건드리지 않는다
    mkdir -p .nexi-tmp/t57-check/fakebin
    printf '#!/bin/sh\necho v99.99.99\n' > .nexi-tmp/t57-check/fakebin/node
    chmod +x .nexi-tmp/t57-check/fakebin/node
    PATH=".nexi-tmp/t57-check/fakebin:$PATH" BACKEND_PORT=28080 FRONTEND_PORT=25173 make run
    echo "exit=$?"   # 0이 아니어야 함
    git status --porcelain -- .nvmrc   # 빈 출력이어야 함(.nvmrc를 쓰지 않았다는 증거)

    # (b) 포트 사용 중일 때 거부 — 더미 리스너로 28080(검증용 포트)을 점유
    node -e 'require("net").createServer().listen(28080)' &
    dummy=$!
    BACKEND_PORT=28080 FRONTEND_PORT=25173 make run; echo "exit=$?"   # 0이 아니어야 함
    kill $dummy

    # (c) 정상 기동과 Ctrl-C로 함께 내려가는지
    BACKEND_PORT=28080 FRONTEND_PORT=25173 make run & runner=$!
    # http://localhost:25173/api/health, http://localhost:28080/api/health 가 응답할 때까지 대기(최대 60초)
    kill -INT $runner
    # 두 포트(28080/25173)가 다시 비는지 확인
    ```
  - `make reset-db`의 통합 확인(기준 3, 전부 격리된 임시 경로·포트로 돈다):
    ```
    # 실제 시연 DB는 손대지 않는다는 증거 — 확인 전체에 걸쳐 체크섬을 둘러 비교
    before=$(cksum backend/data/app.db 2>/dev/null || echo "없음")

    # (i) 임시 경로에 더미 DB·WAL·journal 준비, 포트(28080) 비어 있을 때: 지워져야 함
    mkdir -p .nexi-tmp/t57-check
    : > .nexi-tmp/t57-check/app.db
    : > .nexi-tmp/t57-check/app.db-wal
    : > .nexi-tmp/t57-check/app.db-journal
    RESET_DB_PATH=.nexi-tmp/t57-check/app.db BACKEND_PORT=28080 make reset-db
    ls .nexi-tmp/t57-check/app.db .nexi-tmp/t57-check/app.db-wal .nexi-tmp/t57-check/app.db-journal 2>&1   # 셋 다 없어야 함

    # (ii) 다시 준비 + 포트(28080) 점유 상태에서: 지워지지 않아야 함
    : > .nexi-tmp/t57-check/app.db
    node -e 'require("net").createServer().listen(28080)' &
    dummy=$!
    RESET_DB_PATH=.nexi-tmp/t57-check/app.db BACKEND_PORT=28080 make reset-db; echo "exit=$?"
    ls .nexi-tmp/t57-check/app.db   # 그대로 있어야 함
    kill $dummy

    # (iii) 저장소 밖 경로는 거부되는지
    : > /tmp/t57-outside.db
    RESET_DB_PATH=/tmp/t57-outside.db BACKEND_PORT=28080 make reset-db; echo "exit=$?"   # 0이 아니어야 함
    ls /tmp/t57-outside.db   # 그대로 있어야 함(지워지지 않음)
    rm -f /tmp/t57-outside.db

    # 실제 시연 DB가 전혀 바뀌지 않았다는 증거
    after=$(cksum backend/data/app.db 2>/dev/null || echo "없음")
    [ "$before" = "$after" ] && echo "시연 DB 그대로" || echo "경고: 시연 DB가 바뀜"
    ```
