## 목록 API의 `skills` (백엔드)

`GET /api/employees`의 각 항목 끝에 `skills`를 더한다. 다른 필드, 쿼리, 필터 결과, 항목 순서(`id` 오름차순)는 바꾸지 않는다.

```json
{
  "id": 1, "name": "박소영", "departmentId": 1, "departmentName": "개발팀",
  "jobTitle": "백엔드 개발자", "careerYears": 5,
  "availabilityStatus": "AVAILABLE", "currentAvailability": 40, "needsReview": false,
  "skills": [{"skillName": "Java", "proficiencyLevel": "ADVANCED"}]
}
```

- `skills`는 항상 배열이다. 기술이 없으면 `[]`이고 `null`이나 빠진 키가 아니다.
- 원소는 정확히 두 키 `skillName`(문자열, 저장된 그대로)과 `proficiencyLevel`(`BEGINNER`·`INTERMEDIATE`·`ADVANCED`)이다.
  상세(`GET /api/employees/{id}`)의 `skills` 원소와 같은 모양이다.
- 순서는 그 직원 기술 줄의 저장 순서(`employee_skill.id` 오름차순)다. 등록·수정은 요청 배열 순서대로 줄을 넣으므로, 곧 마지막
  등록·수정 요청의 `skills` 순서다.
- 목록의 `skill` 필터는 지금처럼 `skillName`과 정확히 같은 줄이 있는 직원만 남긴다(#8). 걸러진 직원의 `skills`에는 그 직원의
  모든 기술 줄이 들어간다(필터에 맞은 줄만이 아니다).
- 시드 값(2026-10-13 임시 DB로 확인): `박소영` `[{"skillName":"Java","proficiencyLevel":"ADVANCED"}]`, `최동훈`
  `[{"skillName":"React","proficiencyLevel":"INTERMEDIATE"}]`, `한지우` `[{"skillName":"Java","proficiencyLevel":"BEGINNER"}]`,
  나머지 17명 `[]`.

## 화면 동작

### 구성 (BRIEF 6.3, 넓은 구간 ≥1024px)

1. 제목 "직원"(h1, xl/700).
2. 이름 검색: `TextField`, 라벨 "이름 검색", `type="search"`, 최대 너비 400px (제안).
3. 필터: `SelectField` 네 개 "부서", "기술", "투입 상태", "가용률"을 한 줄에 같은 너비로, 사이 `--space-3`(12px).
   - 1280px(본문 996px): (996 − 3 × 12) ÷ 4 = 240px씩. 1024px(본문 740px): (740 − 36) ÷ 4 = 176px씩.
   - 가장 긴 선택지("디자인팀", "투입 불가", "70% 이상")는 md 글자로 약 70px이고, 좌우 패딩과 화살표를 더해도 약 120px라 176px
     안에 들어간다.
4. 결과 수 "N명"(sm, text-muted). 목록을 받았고 1명 이상일 때만 보인다.
5. 표(`DataTable`) 열: 이름 · 부서 · 직무 · 기술 · 투입 상태 · 현재 가용률 · 확인 필요.
   - 이름은 일반 글자다. 링크(`a`)를 두지 않는다. 상세 화면과 그 경로는 #14가 만들고, 이름을 상세 링크로 바꾸는 일도 #14가
     한다(FDE 결정, 2026-10-13: 갈 곳 없는 임시 링크를 두지 않는다).
   - 기술은 `skills`의 `skillName`을 API 순서대로 `, `로 잇는다(숙련도는 상세 화면의 몫). 없으면 `—`(text-muted, BRIEF 5절).
   - 투입 상태는 `Badge`: `투입 가능`(success/success-bg), `투입 불가`(danger/danger-bg).
   - 현재 가용률은 `40%`처럼 정수와 `%`, 끝 정렬, `tabular-nums`(BRIEF 5절).
   - 확인 필요는 `needsReview`가 참이면 `Badge` `확인 필요`(warning/warning-bg), 아니면 `—`(text-muted).
   - 7열의 1024px 너비는 740px이다. 배지(`white-space: nowrap`, 약 66px)와 셀 패딩 32px를 더해도 열 최소 너비가 약 98px이고,
     나머지 글자는 줄바꿈되므로(BRIEF 5절 "긴 값") 넘치지 않는다. 기준 11이 잰다.

### 좁은 구간 (<1024px, 본문 360px에서 328px)

- 검색은 그대로 보인다(전체 너비).
- 그 아래에 secondary 버튼 "필터"가 있다. 네 필터 중 "전체"가 아닌 것이 N개면 글자가 "필터 (N)"이다(이름 검색은 세지 않는다)
  (제안). 버튼은 `aria-expanded`와 `aria-controls`(필터 영역)를 둔다.
- 필터 영역은 처음에 접혀 있고, 버튼을 누르면 펼쳐지거나 접힌다. 펼치면 네 `SelectField`가 한 열(각 328px)로 쌓인다.
- 넓은 구간에서는 이 버튼을 그리지 않고(`display: none`) 필터 영역은 접힘 상태와 관계없이 항상 보인다.
- 표는 카드가 된다(`DataTable`). 카드 제목은 이름이다.

### 필터와 주소 (제안, #15와 같은 방식)

- 필터는 주소의 쿼리에 있다. 키는 API와 같다: `name`, `departmentId`, `skill`, `status`, `minAvailability`. 값을 바꾸면 쿼리를
  `replace`로 바꾸고(검색어를 칠 때마다 방문 기록이 쌓이지 않게) 새로 불러온다. 새로고침과 뒤로 가기 뒤에도 같은 필터다.
- 선택지:
  - 부서: "전체" + **선택지 응답**(아래)의 항목에 나온 부서를 중복 없이 `departmentId` 오름차순으로(글자는 `departmentName`,
    값은 id).
  - 기술: "전체" + **선택지 응답**의 모든 항목의 `skills[].skillName`을 중복 없이 모아 `localeCompare(…, 'ko')` 순서로. 값은
    `skillName` 그대로다(서버의 `skill` 필터가 정확히 일치로 거르므로 대소문자도 그대로 둔다). 숙련도는 선택지에 쓰지 않는다.
  - 투입 상태: "전체", "투입 가능"(`AVAILABLE`), "투입 불가"(`UNAVAILABLE`).
  - 가용률 (제안): "전체", "30% 이상", "50% 이상", "70% 이상", "100%" → `minAvailability` 30, 50, 70, 100.
- **선택지 응답**은 화면을 열 때 부르는 필터 없는 `GET /api/employees`의 응답이다. 부서·기술 선택지는 이 응답으로 한 번만 만들고,
  검색어나 필터를 바꿔도 다시 만들지 않는다. 그래서 현재 결과에 없는 부서·기술도 선택지에 남는다(예: "디자인팀"을 골라 기술이
  있는 직원이 하나도 없어도 기술 선택지는 그대로다). 선택지는 화면을 다시 열 때(새로고침 포함)와, 선택지 요청이 실패한 뒤 "다시
  시도"할 때만 다시 만든다. 선택지 응답이 비면 부서·기술 선택지는 "전체" 하나다.
- 주소에서 읽은 값은 검사한다. 이름은 앞뒤 공백을 지우고 비면 없는 것으로 본다. `departmentId`는 부서 선택지의 id, `skill`은
  기술 선택지, `status`는 두 값, `minAvailability`는 네 값 중 하나여야 한다. 아니면 그 필터는 "전체"로 보고 요청에 넣지 않는다.
- 요청: 처음 열 때 선택지 응답을 받으려고 `GET /api/employees`(쿼리 없음)를 한 번 부른다. 유효한 필터가 없으면 그 응답이 곧 목록이다
  (요청 1번). 있으면 이어서 `GET /api/employees?<유효한 필터>`를 부른다. 그 뒤 필터를 바꿀 때는 필터 요청만 보낸다. 쿼리 순서는
  `name`, `departmentId`, `skill`, `status`, `minAvailability`이고 값은 URL 인코딩한다.

### 불러오는 동안과 상태 (D35)

- **불러오는 중** (BRIEF 3.3): 결과 자리 가운데에 `Spinner` 24px와 "불러오는 중…"(sm, text-muted)을 두고 그 영역에
  `aria-busy="true"`를 둔다. 검색과 필터는 그대로 쓸 수 있다.
- **오류**: 선택지 요청이나 목록 요청이 네트워크 오류이거나 2xx가 아니면(401 포함) 결과 자리에 `StateMessage` `error`와 "다시
  시도"를 둔다. "다시 시도"는 실패한 요청부터 다시 부른다.
- **빈 목록**: 유효한 필터가 하나도 없는데 결과가 비면 `StateMessage` `empty`, 제목 "등록된 직원이 없습니다".
- **검색 결과 없음**: 유효한 필터가 하나라도 있는데 결과가 비면 `StateMessage` `no-results`, 제목 "조건에 맞는 직원이 없습니다",
  "필터 초기화". 누르면 이름과 네 필터를 모두 지우고(주소 `/employees`) 필터 없이 부른다.
- **지연 응답과 겹친 요청**: 필터나 검색어가 바뀌면 앞의 요청을 끊고(`AbortController`), 그 응답이 나중에 와도 화면을 바꾸지
  않는다. 항상 마지막 필터의 응답만 보인다. 오류 뒤 "다시 시도"도 같다.

### 컴포넌트 값

- **`SelectField`** (BRIEF 3.2 "선택 상자는 TextField와 같은 높이·테두리"): 라벨은 위(sm/600, text, 아래 4px). `select`는 높이
  40px, 좌우 패딩 12px(화살표 자리로 오른쪽 36px) (제안), 배경 surface, 테두리 1px border-strong, 반경 `--radius-sm`, 글자
  md/400, 너비는 칸 전체. hover 테두리 text-muted, 포커스는 BRIEF 3절 공통 규칙. 라벨과 `select`는 `htmlFor`/`id`로 잇는다.
- **`Spinner`** (BRIEF 3.3, 회전 모양은 3.1의 loading 버튼과 같은 규칙): 24px 원형 회전 표시, 색 text-muted, `aria-hidden`.
  `prefers-reduced-motion: reduce`에서는 돌지 않는다. 버튼 안의 16px 회전 표시(T#4)는 바꾸지 않는다.
- **`Badge` 직원 변형** (BRIEF 3.6): `AVAILABLE` "투입 가능" success/success-bg(대비 5.19), `UNAVAILABLE` "투입 불가"
  danger/danger-bg(5.09), `NEEDS_REVIEW` "확인 필요" warning/warning-bg(5.52). 공통 모양(xs/600, 패딩 2px 8px,
  `--radius-full`)은 #15 그대로다. 요소에 `data-status`로 값을 둔다.
