# T#34 프로젝트 등록·수정 폼

## 산출물

프로젝트 관리자가 넓은 구간(≥1024px)에서 목록의 "프로젝트 등록"과 상세의 "수정"으로 프로젝트를 등록·수정(필요 역량 줄 추가·삭제)하고, 서버가
돌려준 위반 원인(D30 포함)이 그 입력 아래 보이며, 좁은 구간의 폼 주소에서는 데스크톱 이용 안내가 보이는 화면이 있다.

이슈 #34 그대로 하나로 한다. 예상 약 8.25시간이라 하루(8시간)를 조금 넘을 수 있다. 더 나누려면 PM이 `nexi-backlog split 34`로 나눈다.

### 등록 `/projects/new`, 수정 `/projects/:id/edit` (BRIEF 6.6 폼)

- 제목(h1): "프로젝트 등록", "프로젝트 수정".
- 불러오기: 등록은 요청 없이 빈 폼을 그린다. 수정은 `GET /api/projects/{id}`를 부르고, 그동안 `Spinner`와 "불러오는 중…",
  `aria-busy="true"`다. 실패하면 StateMessage `error`(API `message`가 있으면 그 글자, 404는 "프로젝트를 찾을 수 없습니다.")와 "다시
  시도"이고, 다시 시도는 그 요청을 다시 보낸다.
- `form`은 `noValidate`다. 한 열, 최대 너비 720px, 필드 사이 `--space-4` (제안: 필요 역량 한 줄이 한 줄에 들어가는 너비, 아래 "화면"
  계산). 필드 순서(D3):
  1. 프로젝트명 `*` — `TextField`.
  2. 설명 — `TextField` 한 줄 (제안). 수정에서 API 값이 `null`이면 빈 칸이다.
  3. 기간 — `fieldset`(legend "기간", sm/600). 안에 `TextField` `type="date"` "시작일" `*`, "종료일" `*`이 한 줄에 `1fr 1fr`, 간격
     `--space-2` (제안).
  4. 상태 `*` — `SelectField`: "선택하세요"(빈 값), "계획" `PLANNED`, "진행 중" `IN_PROGRESS`, "완료" `DONE`, "보류" `ON_HOLD`(D13). 수정은
     그 프로젝트의 상태가 골라져 있다.
  5. 필요 역량 — `fieldset`(legend "필요 역량", sm/600). 줄마다 `role="group"` `aria-label="필요 역량 N"`(N은 1부터)이고, 그 안에
     `TextField` "직무", `TextField` "기술", `SelectField` "숙련도"("선택하세요", `초급`, `중급`, `고급`, D11), `TextField` "인원"
     (`type="number"`, `min=1`, `step=1`, `inputMode="numeric"`), secondary "삭제"(접근 이름 "필요 역량 N 삭제"). 줄은
     `minmax(0, 1fr) minmax(0, 1fr) 140px 88px auto`, 간격 `--space-2` (제안). 줄 아래 secondary "필요 역량 추가"는 빈 줄을 끝에 더하고
     그 줄의 직무에 포커스를 둔다. 수정은 API 순서대로 줄이 차 있다. 줄이 없으면 "필요 역량 추가"만 있다. 줄 안의 입력에는 `*`를 붙이지
     않는다(줄 자체가 선택이다, #39 기술 줄과 같다).
- 버튼 줄: secondary "취소", primary "저장", 간격 `--space-2` (제안).
- **요청**: 등록 `POST /api/projects`, 수정 `PUT /api/projects/{id}`, `Content-Type: application/json`, 본문은 정확히
  `{"name", "description", "startDate", "endDate", "status", "requiredSkills": [{"jobTitle", "skillName", "proficiencyLevel", "headcount"}]}`.
  - `name`, `jobTitle`, `skillName`은 앞뒤 공백을 지운 글자다(빈 칸이면 `""`). `description`은 앞뒤 공백을 지우고, 비면 `null`이다.
  - `startDate`, `endDate`는 날짜 입력 값(`YYYY-MM-DD`), 비면 `null`이다. `status`, `proficiencyLevel`은 고른 값, 안 골랐으면 `null`이다.
  - `headcount`: 빈 칸이면 `null`. `^-?[0-9]+$`이고 −2147483648–2147483647이면 그 정수. 그 밖(`1.5`, `1e2`, `99999999999`)이면 요청을
    보내지 않고 필요 역량 오류 자리에 "필요 역량의 인원은 정수로 입력하세요."를 보인다 (제안). 0과 음수는 서버가 판단한다.
  - 필요 역량 줄은 화면 순서대로 모두 보낸다(빈 줄도 보내 서버가 판단한다).
- **서버 오류의 자리 (D30, D33)**: 메시지는 API `message` 그대로, TextField 오류 규칙(BRIEF 3.2)으로 보인다.

  | 응답 | 자리 |
  |---|---|
  | 400 `PROJECT_NAME_REQUIRED` | 프로젝트명 아래 |
  | 400 `PROJECT_PERIOD_REQUIRED`, `PROJECT_PERIOD_INVALID`, `PROJECT_PERIOD_EXCLUDES_ASSIGNMENTS` | 기간(시작일·종료일 줄) 아래. "기간" `fieldset`이 `aria-invalid="true"`이고 `aria-describedby`가 메시지를 가리키며, 두 날짜 입력의 테두리가 danger다 (BRIEF 6.6 "기간 입력 아래") |
  | 400 `PROJECT_STATUS_INVALID` | 상태 아래 |
  | 400 `PROJECT_SKILL_LINE_INVALID` (와 화면의 인원 정수 검사) | 필요 역량 줄 아래, "필요 역량 추가" 위. "필요 역량" `fieldset`이 `aria-invalid="true"`이고 `aria-describedby`가 메시지를 가리킨다(#39 기술 구역과 같다) |
  | 그 밖의 `code`(`PROJECT_REQUEST_INVALID` 등), 401·403·404·5xx, `code` 없는 응답, 네트워크 오류 | 버튼 줄 바로 위 폼 메시지(`role="alert"`, danger, 경고 아이콘): API `message`, 없으면 "저장하지 못했습니다. 잠시 후 다시 시도하세요."(#39와 같은 글자) |

  서버가 한 번에 하나를 주므로 화면도 하나를 보인다. 다시 저장하면 앞 메시지를 지운다. 긴 메시지(D30의 세 건)는 폼 너비 안에서
  줄바꿈한다(BRIEF 5절 "긴 값").
- 저장 중에는 "저장"이 loading이고 "취소"가 `disabled`이며, 다시 누르거나 Enter를 눌러도 요청을 더 보내지 않는다.
- 성공: 등록 201이면 응답 `id`의 `/projects/{id}`로, 수정 200이면 `/projects/{id}`로 간다(`replace`). 상세는 그 주소에서 다시
  불러온다(D36).
- 취소: 등록은 `/projects`로, 수정은 `/projects/{id}`로 간다. 요청을 보내지 않는다.

### 데스크톱 이용 안내 (좁은 구간의 폼 주소, D29)

- 1023px 이하에서 프로젝트 관리자가 `/projects/new`나 `/projects/:id/edit`를 열면 제목(h1) 아래에 폼 대신 안내 블록만 보인다. 역할에
  따른 이동(위 표)이 먼저다.
- 안내 블록은 #39와 같은 모양(StateMessage 블록 모양, 아이콘 없음, `role="status"`)이다. 제목 "데스크톱에서 이용해 주세요", 설명
  "프로젝트 등록·수정은 너비 1024px 이상 화면에서 할 수 있습니다.", 그 아래 secondary 버튼 모양의 링크 "프로젝트 목록으로"(등록, →
  `/projects`) 또는 "프로젝트 상세로"(수정, → `/projects/:id`) (제안: 글자).
- 폼 영역(불러오는 중·오류 포함)은 1023px 이하에서 `display: none`이라 보이지 않고 포커스를 받지 않는다. 1024px 이상에서는 안내
  블록이 `display: none`이다. 같은 폼을 숨길 뿐이라 창을 줄였다 넓혀도 입력한 값이 남는다.
- 만드는 법(#39 안내를 공용 부품으로 옮기거나 같은 모양을 따로 두거나)은 정하지 않는다. 옮기면 #39 검사가 고치지 않고 통과해야 한다.
