# T#55 변경: 세션 만료(401) 처리와 로그인 뒤 원래 주소 복귀

변경 대상: T#6, T#13, T#15, T#16, T#17, T#18, T#34, T#38, T#39 (이슈 #55). 배포된 대상 없음(D40). 대상 태스크의 계약서·증거·판정은 고치지 않는다.

## 산출물

로그인한 뒤 업무 요청이 401을 받으면 인증 상태를 비우고 `/login`으로 보내며, 다시 로그인하면 원래 주소로 돌려보내는 프런트엔드 변경: 얇은 `apiFetch` 한 곳(`frontend/src/api/client.ts`)과 그 401 통지를 받는 `AuthProvider`, 주소를 `/login`에 실어 보내고 되돌리는 `AppRoutes`.

## 근거와 발견한 사실

- 회고 보고서 3절 F#1·F#2(브랜치 `retro-2026-10-15`), `docs/ENGINEERING.md` "API 클라이언트" 1항: 401은 `frontend/src/api`의 한 곳에서 처리한다. 그 구현이 이 태스크다.
- 지금 `frontend/src`에서 `fetch(`를 부르는 곳은 13개 파일이다. 업무 요청 10개: `api/assignments.ts:55`, `pages/ProjectAssignPage.tsx:55,107`, `DashboardPage.tsx:78`, `ProjectFormPage.tsx:116,220`, `ProjectListPage.tsx:66`, `EmployeeListPage.tsx:128`, `EmployeeActions.tsx:65`, `ProjectDetailPage.tsx:50`, `EmployeeDetail.tsx:42`, `EmployeeFormPage.tsx:60,196`. 인증 요청: `AuthContext.tsx:41`(`/api/auth/me`), `:77`(`/api/auth/logout`), `LoginPage.tsx:37`(`/api/auth/login`). 그 밖에 `App.tsx:57`(`/api/health`, 인증 없는 공개 요청).
- `AppRoutes.tsx`의 로그아웃 상태 보호 경로는 `<Navigate to="/login" replace />`(주소를 싣지 않음)이고, `/login`은 로그인 사용자를 `homePath(user)`로 보낸다. 그래서 딥링크는 로그인 뒤 항상 `/`나 `/me`로 간다.
- `DashboardPage.test.tsx:244`의 `it.each`는 401을 "일반 조회 실패"로 고정한다(헤더 이름 유지, 다시 시도).

## 결정 (제안 — 승인하면 이 계약의 결정이 된다)

1. **감싸기 방식.** `apiFetch(input, init)`는 호출 시점의 전역 `fetch(input, init)`를 같은 인자 그대로 부르고 응답을 그대로 돌려준다(본문·`signal`·헤더 보존, 자동 재전송 없음). 응답 상태가 401이면 만료를 알린다. 전역 `fetch`를 바꾸지 않는다. 응답 파싱·`readFailure`·리소스 함수는 옮기지 않는다.
2. **제외.** `/api/auth/login`, 초기 `/api/auth/me`, `/api/auth/logout`, `/api/health`는 `apiFetch`를 쓰지 않는다(전과 같이 `fetch`). 추가로 `apiFetch`는 `/api/auth/`로 시작하는 주소의 401을 만료로 보지 않는다.
3. **취소.** 요청이 거절(`AbortError` 포함)되면 그대로 던지고 만료로 보지 않는다. 이미 `signal.aborted`인 요청의 401도 만료로 보지 않는다.
4. **통지.** `AuthProvider`가 `apiFetch`에 만료 처리기를 등록한다. 처리기는 `user`를 `null`로 만든다(`status`는 `ready`). 이미 `user`가 없으면 아무것도 하지 않는다.
5. **동시 401과 재로그인 뒤 도착한 이전 요청.** 인증 세대 번호를 둔다. 요청은 시작할 때의 세대를 기억하고, `signIn`과 만료는 세대를 올린다. 응답 때 세대가 다르면 그 401은 무시한다(새 세션을 끊지 않는다). 같은 세대의 401이 여럿이면 처음 것만 일하고 나머지는 무시한다.
6. **원래 주소.** 로그아웃 상태 보호 경로(`ManagerOnly`, `/me`)는 `<Navigate to="/login" replace state={{ from: 경로+쿼리+해시 }} />`로 보낸다. `/login`은 로그인한 사용자를 `state.from`이 안전하면 거기로, 아니면 `homePath(user)`로 보낸다. 안전 = 문자열, `/`로 시작, `//`·`/\`로 시작하지 않음, 경로가 `/login`이 아님. 역할 가드는 목적지의 기존 가드를 그대로 쓴다(직원 계정이 `/projects/5`로 돌아오면 `/me`로, 프로젝트 관리자가 아닌 계정이 `/projects/new`로 돌아오면 `/projects`로).
7. **`*` 경로**는 `from`을 싣지 않는다(없는 주소로는 돌아오지 않는다). 로그인 화면의 모양·문구는 바꾸지 않는다(만료 안내 문구 없음).

## 수용 기준

1. 로그인한 사용자가 `/projects/5`에서 조회 요청이 401을 받으면 화면은 `/login`으로 간다. 로그인 화면이고, 헤더의 로그인 이름도 "다시 시도" 오류도 없다. — 확인: `AppRoutes.session.test.tsx` "조회 401 → /login" (실제 `AuthProvider`·`AppRoutes`·`MemoryRouter`, 전역 `fetch`만 가짜)
2. 쓰기 요청(POST·PATCH·DELETE)이 401을 받아도 같다. 그 요청은 정확히 한 번만 보내진다(자동 재전송 없음). — 확인: 같은 파일 "쓰기 401" (`fetchMock` 호출 수 1)
3. 다시 로그인하면 원래 주소 `/projects/5?tab=x#y`(경로·쿼리·해시)로 돌아온다. 로그아웃 상태로 딥링크를 열었을 때도 같다. — 확인: 같은 파일 "복귀 (만료)", "복귀 (딥링크)"
4. 목적지는 내부 경로만 받는다. `state.from`이 `https://evil.example`, `//evil.example`, `/\evil`, `/login`, 문자열이 아님이면 `homePath(user)`로 간다. 역할 가드가 적용된다(직원 계정은 `/projects/5`가 아니라 `/me`). — 확인: 같은 파일 "복귀 (안전하지 않은 주소 6종)", "복귀 (역할 가드)"
5. 로그인 요청·초기 `/api/auth/me`·로그아웃의 401은 만료로 다루지 않는다: 로그인 실패는 비밀번호 칸 아래 서버 메시지를 그대로 보이고, 초기 `/me` 401은 로그인 화면, 로그아웃 401은 로그아웃 성공으로 전과 같다. — 확인: 같은 파일 "제외 3종" + 기존 `LoginPage.test.tsx`·`AppRoutes.test.tsx`(회귀)
6. 취소는 만료가 아니다. 요청이 `AbortError`로 거절돼도, 중단된 `signal`의 응답이 401이어도 사용자는 로그인된 채 남는다. — 확인: `client.test.ts` "취소"
7. `apiFetch`는 인자를 보존한다: 같은 URL, 같은 `init` 객체(본문·헤더·`signal` 포함)로 전역 `fetch`를 한 번 부르고, 응답 객체를 그대로 돌려주며, 401이어도 던지지 않는다. — 확인: `client.test.ts` "인자 보존"
8. 동시에 401이 둘이면 `/login`으로 한 번만 가고 `from`은 첫 요청의 주소다(`/login`을 거친 이력이 하나). — 확인: `AppRoutes.session.test.tsx` "동시 401"
9. 다시 로그인한 뒤 이전 세션에서 시작한 요청이 401로 도착해도 새 세션은 끊기지 않는다(사용자 이름 유지, `/login`으로 가지 않음). — 확인: 같은 파일 "재로그인 뒤 늦은 401"
10. 업무 요청은 모두 `apiFetch`를 쓴다. `frontend/src`에서 `fetch(`를 직접 부르는 비테스트 파일은 `api/client.ts`, `auth/AuthContext.tsx`, `pages/LoginPage.tsx`, `App.tsx`뿐이다. — 확인: `client.test.ts` "fetch 직접 호출 목록"(소스를 읽어 허용 목록과 비교)
11. `DashboardPage.test.tsx`의 `it.each`에서 401 항목이 빠지고(네트워크 거절·500만 남는다), 401은 화면 수준(기준 1)에서 검사한다. 네트워크 거절·500의 "데이터를 불러오지 못했습니다 / 다시 시도"는 그대로다. — 확인: `DashboardPage.test.tsx`(회귀: 남은 두 항목)
12. 실제 백엔드에서: 로그인한 브라우저의 세션 쿠키를 지운 뒤 메뉴로 `/employees`를 열면 `/login`으로 가고, 다시 로그인하면 `/employees`로 돌아온다. 새 브라우저로 `/projects/1`을 열면 `/login`, 로그인하면 `/projects/1`이다. — 확인: `frontend/e2e/session-expiry.spec.ts` (`make test`의 `e2e` 프로젝트, 읽기만 하므로 DB를 바꾸지 않는다)
