# T#3 Skeleton: Spring Boot·React·SQLite 구조와 make 명령

## 산출물

`backend/`(Java 21, Spring Boot 3.5.16, Maven Wrapper)와 `frontend/`(Node 24 LTS, React 19.3.0, TypeScript 7.0.2, Vite 8.3.4)의 뼈대 구조가 있고, README 순서대로 하면 `make build`·`make test`·`make lint`가 통과하며 빈 SQLite 파일과 백엔드 상태 API, 프런트엔드 첫 화면이 뜬다.

## 수용 기준

1. `backend/`에 Maven Wrapper(`./backend/mvnw`, Maven 3.10.0)로 빌드되는 Spring Boot 3.5.16 프로젝트가 있고 `java.version`이 21로 고정돼 있다 — 확인: `backend/mvnw -v` 출력에 Maven 3.10.0, Java 21이 보임.
2. `frontend/`에 Vite 8.3.4 + React 19.3.0 + TypeScript 7.0.2 프로젝트가 있고 Node 24 LTS·npm 전제가 `package.json`(`engines`)과 `.nvmrc`에 적혀 있다 — 확인: `.nvmrc`=`24.21.0`, `frontend/package.json`의 `engines.node`="24.x", 의존성 버전이 위와 일치.
3. `make build`가 backend(`./backend/mvnw -f backend/pom.xml package`)와 frontend(`npm --prefix frontend run build`)를 순서대로 실행해 성공한다 — 확인: `make build` (현재는 "not set up yet"로 실패 → 작업 후 성공).
4. `make test`가 backend 테스트(상태 API 테스트, DataSource 연결/파일 생성 테스트)와 frontend 테스트(최소 1개 컴포넌트 테스트)를 실행해 모두 통과한다 — 확인: `make test` (현재는 실패 → 작업 후 성공).
5. `make lint`가 backend(Maven 컴파일 경고 0건 기준 또는 Checkstyle 중 하나)와 frontend(`eslint`)를 실행해 통과한다 — 확인: `make lint` (현재는 실패 → 작업 후 성공).
6. 빈 SQLite 파일 생성: 설정된 경로(`backend/data/app.db`)에 앱을 처음 실행할 때 SQLite 파일이 새로 만들어지고, 이 파일은 git에 포함되지 않는다 — 확인: 자동 테스트가 임시 디렉터리에서 애플리케이션 컨텍스트를 올리고 DataSource로 연결해 파일 생성을 확인함; `.gitignore`의 `*.db`/`*.sqlite*` 규칙으로 git 추적 제외 확인.
7. 백엔드 상태 API `GET /api/health`가 200과 `{"status":"UP"}` 형태 응답을 돌려준다 — 확인: `@SpringBootTest` + `MockMvc`(또는 `WebTestClient`) API 테스트.
8. 프런트엔드 첫 화면이 뜨고 백엔드 상태 API를 호출해 그 값을 보여 준다 — 확인: 최소 1개 컴포넌트 테스트(호출 결과를 화면에 표시하는지) + `npm run build && npm run preview`로 수동 확인.
9. 클린 클론(원격을 새 폴더에 clone)에서 README의 설치·설정·실행 순서대로 하면 1–8이 모두 된다 — 확인: 새 임시 폴더에 clone 후 README 순서를 그대로 실행.
10. `README.md`에 Java 21(OpenJDK, 로컬 확인 버전 21.0.12)·Node 24 LTS(24.21.0)·npm(11.19.0) 버전, 설치·설정·실행 순서(백엔드와 프런트엔드 각각), SQLite 파일 위치가 적혀 있다 — 확인: README를 사람이 그대로 따라 함(기준 9와 같은 실행으로 겸함).

## 검증 명령

- 새 검사: `make build`, `make test`, `make lint` — 이 태스크 이전에는 Makefile이 "not set up yet"으로 항상 실패하므로(기존 상태) 세 명령 모두 이 태스크의 새 검사다. 작업 전 실패(현재 상태 그대로) → 작업 후 통과.
- 회귀 검사: 없음. skeleton 태스크라 이전에 통과하던 검사가 없다.

## 하지 않을 일

- 직원·프로젝트·배치 데이터 모델, 저장소 계층 구현, 시드 데이터 (→ T#5).
- 로그인·권한 검사 (→ T#6).
- 디자인 토큰·레이아웃 셸·기본 컴포넌트, `make screenshots` (→ T#4, 디자인 시스템 태스크).
- 실제 업무 화면(목록·상세·배치) 구현.
