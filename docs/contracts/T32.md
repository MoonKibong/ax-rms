# T#32 프로젝트 목록 인력 부족 표시

## 산출물

`GET /api/projects`의 항목마다 D20 기준 인력 부족 여부 `understaffed`(boolean)가 있고(판정은 #11의 서비스 메서드 하나를 그대로 쓴다), 프로젝트 목록 화면이 표의 마지막 열 "인력 부족"에 그 값으로 warning 배지를 보인다.

## 전제

- **선행 작업 #11은 `main`에 있다**(PR #45, `fab91f9`). 이 계약서는 `origin/main`(`fab91f9`, #11·#34 병합 뒤)을 읽고 썼고, 재사용할 판정은 `main`의 코드 그대로다:
  `com.ax.rms.dashboard.DashboardService.shortStaffedProjectIds`는 `public static`이다. 인자는
  `List<Project> projects, List<Assignment> assignments, List<EmployeeSkill> employeeSkills, List<ProjectRequiredSkillLine> requiredLines, LocalDate today`,
  반환은 `List<Long>`(`IN_PROGRESS`인 프로젝트만, id 오름차순)다. `GET /api/dashboard`(`DashboardController`)의 `shortStaffedProjects`는
  `[{id, name, requiredHeadcount, assignedHeadcount, missingSkills:[{skill, requiredHeadcount}]}]`이고 같은 판정을 쓴다. PM 결정(이슈 #11 댓글 2026-10-13): 이 태스크는 #11의 판정을 프로젝트 목록
  API에서 재사용한다(PM이 이 계약서를 #11 병합 뒤에 승인하기로 했다, 이슈 #32 댓글 2026-10-14).
- 근거: REQ-CONTEXT D3, D13, D19, D20, D29, D33, D34, D35, D36. 화면은 `docs/design/BRIEF.md` 6.5절(프로젝트 목록: "표: … · 인력 부족 배지"), 3.3절(DataTable), 3.6절
  Badge(`인력 부족` warning/warning-bg), 5절, 7절을 따른다. BRIEF가 정하지 않은 값은 `(제안)`이다.
- #15 계약서(PM 결정)가 "인력 부족" 열을 이 태스크로 넘겼다. 그래서 T#15의 목록 검사 몇 곳이 이 태스크의 새 열과 어긋난다(기준 7의 예외).
- **판정(D20)은 백엔드 한 곳이다(D36).** 화면은 `understaffed`를 그대로 보이고 필요 인원·배치 인원으로 스스로 판정하지 않는다. "오늘"은 서버 `Clock`이다(D19).
- 권한(D9, D25): 목록 조회는 두 관리자 모두, 직원만은 403, 비로그인은 401 그대로다(#6 `AuthorizationPolicyTest`). 새 필드는 목록을 볼 수 있는 계정에게 같이 보인다. 이 태스크는 권한 규칙을
  바꾸지 않는다.
- **시드(`SeedRunner`, 고정 `Clock` 2026-06-15, 2026-10-14 소스에서 읽음).** `IN_PROGRESS`는 알파·베타 둘이다. 알파는 필요 Java×2에 오늘 배치 박소영·강민재·권지안 3명이고 Java 보유자 박소영이
  있어 부족이 아니다. 베타는 필요 React×2에 오늘 배치 최동훈·임도윤·안유진 3명이고 React 보유자 최동훈이 있어 부족이 아니다. 감마(`DONE`)·델타(`PLANNED`)·엡실론(`ON_HOLD`)은 `IN_PROGRESS`가
  아니어서 대상이 아니다. 그래서 **시드의 다섯 프로젝트는 모두 `understaffed: false`**다(#11 계약서의 `shortStaffedProjects: []`와 같다). 실제 e2e DB는 날짜가 DB를 만든 날 기준이라 같은 결론이다.
- 이 태스크의 리뷰는 PM이 한다(이슈 #32 본문 "리뷰: PM"). 권한·데이터 삭제·외부 서비스를 바꾸지 않는다.
- `make`가 설치되어 있지 않은 환경에서는 Makefile의 각 줄을 같은 명령으로 실행해 증거에 적는다.

## API 변경 (백엔드)

- `ProjectSummary`(`GET /api/projects`의 항목)에 `boolean understaffed`를 더한다. 항목 키는 지금의 `id, name, startDate, endDate, status, requiredHeadcount, assignedHeadcount`에 이것 하나가 더해진다.
- `ProjectService.list`는 전체 프로젝트·배치·직원 기술·필요 역량 줄을 읽어 `DashboardService.shortStaffedProjectIds`를 **한 번** 부르고, 항목의 `understaffed`는 그 id 목록에 들어 있는지다. 상태
  필터(`?status=`)는 보이는 항목만 거를 뿐 판정에는 영향이 없다(필터 때문에 값이 달라지지 않는다). 판정 코드를 이 서비스에 복사하지 않는다.
- `GET /api/projects/{id}`(상세)·쓰기 API·`README`의 다른 표는 바꾸지 않는다.

## 화면 동작

- 표(≥1024px)의 열: 프로젝트명 · 상태 · 기간 · 필요 인원 · 배치 인원 · **인력 부족**(마지막 열). 좁은 구간(<1024px)은 카드이고 "인력 부족 — 값" 줄이 마지막이다(DataTable).
- 값: `understaffed`가 `true`이면 `Badge`(글자 "인력 부족", warning/warning-bg, `data-status="UNDERSTAFFED"`), 아니면 "—"(직원 목록의 "확인 필요"와 같은 글자와 모양 `(제안)`).
  배지는 색만이 아니라 글자로 쓴다(D13, BRIEF 3.6).
- 나머지(상태 필터, 불러오는 중·오류·빈 목록·결과 없음 상태, 이름 링크, 기간 줄바꿈, 등록 버튼)는 T#15·T#16 그대로다.
- **`Badge`의 `인력 부족` 변형은 #18(대시보드)도 쓴다**(BRIEF 3.6 "대시보드: `인력 부족`"). 먼저 머지된 태스크가 `BadgeStatus`에 `UNDERSTAFFED`를 더하고, 나중 태스크는 쓰기만 한다. **구현을 시작하기 전과 `origin/main`을
  병합한 뒤, `main`의 `BadgeStatus`에 `UNDERSTAFFED`가 있는지 확인하고 있으면 만들지 않고 쓴다**(PM 결정, 이슈 #32 댓글). 없으면 `Badge.tsx`·`Badge.css`에 만든다(같은 색: `--color-warning`/`--color-warning-bg`).
  2026-10-14 `main`(`fab91f9`)에는 아직 없다(`grep UNDERSTAFFED frontend/src` 결과 없음).

## 수용 기준

1. **판정 재사용과 새 필드(D20, D36).** `GET /api/projects`의 모든 항목에 boolean `understaffed`가 있다. 시드로는 다섯 항목 모두 `false`다. 판정은 #11의 `shortStaffedProjectIds`를 호출해서 얻는다(복사 없음).
   - 확인: `ProjectUnderstaffedTest.seeded`(`AbstractApiTest`, 고정 `Clock`, `project.manager` 로그인). 준비: `ProjectSummary`에 필드가 없다. 레드: `understaffed` 키가 없어 `isBoolean()` 단언이 실패한다.
2. **부족 상황(D20 두 조건, 상태 필터).** 테스트 안에서 저장소로 시드를 바꿔 부족을 만든다: (a) 알파의 오늘 배치를 전부 지운다 → 알파 `true`(조건 1: 오늘 배치 0 < 필요 2), 베타 `false`; (b) 알파에 Java 없는 직원 둘을 오늘
   포함 배정으로 더한다 → 알파 `true`(조건 2: 필요 역량 줄의 기술 보유자 없음); (c) 알파에 Java 보유자 박소영과 한지우를 더한다 → 알파 `false`. `DONE`·`PLANNED`·`ON_HOLD` 프로젝트는 배치가 없어도 항상 `false`다.
   `?status=IN_PROGRESS`로 불러도 같은 항목이 같은 값을 갖는다.
   - 확인: `ProjectUnderstaffedTest.shortStaffedCases`, `statusFilterKeepsTheValue`. 준비·레드: 기준 1과 같다.
3. **대시보드 API와 같은 프로젝트(D36).** 기준 2의 각 상황에서, 목록 API에서 `understaffed`가 `true`인 프로젝트의 id 집합이 `GET /api/dashboard`의 `shortStaffedProjects[].id` 집합과 같다(시드에서는 둘 다 빈
   집합).
   - 확인: `ProjectUnderstaffedTest.sameProjectsAsDashboard`(`main`의 `GET /api/dashboard`). 준비·레드: 기준 1과 같다.
4. **목록 화면의 열과 배지(Vitest).** 가짜 응답으로: 표 머리글이 여섯(프로젝트명, 상태, 기간, 필요 인원, 배치 인원, 인력 부족), `understaffed: true`인 항목에만 `data-status="UNDERSTAFFED"` 배지("인력 부족"), 아닌 항목은
   "—"다. 판정은 응답 값만 따른다(필요 인원이 배치 인원보다 커도 `understaffed: false`이면 배지가 없다). `Badge`가 `UNDERSTAFFED`를 쓴다.
   - 확인: Vitest `ProjectListPage.understaffed.test.tsx`, `Badge.test.tsx`의 새 테스트. 준비: `understaffed` 타입과 열이 없다. 레드: 머리글이 다섯이고 배지가 없어 단언이 실패한다.
5. **모양과 값 (e2e, 실제 시드, 읽기만).** `frontend/e2e/projects-understaffed.spec.ts`. `project.manager`로 `/projects`: 1280px 표 머리글 여섯째가 "인력 부족", 360px 카드에 "인력 부족" 라벨. 실제 `GET /api/projects`를
   페이지 안에서 불러 다섯 항목 모두 `understaffed: false`이고 화면에 "인력 부족" 배지가 없다. 가로챈(`page.route`) 응답으로 알파만 `true`이면 알파 행에만 배지가 있고 글자 색 `rgb(143, 83, 0)`, 배경
   `rgb(253, 241, 220)`이며, 1280/1024/1023/360px에서 가로 넘침이 없다. 이 검사는 실제 서버에 쓰기 요청을 보내지 않는다.
   - 확인: Playwright `frontend/e2e/projects-understaffed.spec.ts`. 준비: 열이 없다. 레드: 여섯째 머리글이 없어 단언이 실패한다.
6. **실제 저장 뒤의 값 (e2e 저장, D20, D36).** `frontend/e2e/write/project-understaffed.spec.ts`를 `scripts/e2e-servers.sh --fresh-db`로 돌린다. `project.manager`로: 알파의 배치 셋을 API로 해제 → 목록 화면의 알파 행에 "인력
   부족" 배지, 다른 행에는 없음, 목록 API와 `GET /api/dashboard`의 `shortStaffedProjects`가 같은 프로젝트를 가리킴, `page.reload()` 뒤에도 같음; 이어서 박소영과 한지우(둘 다 Java 보유)를 알파 기간 안에 오늘 포함 배정 → 배지가 사라지고
   두 API가 다시 같음. 날짜는 API가 준 `today`와 프로젝트 기간에서 계산한다.
   - 확인: Playwright `e2e-write` 프로젝트. 준비: 스펙만 둔다. 레드: 목록에 "인력 부족" 머리글이 없어 첫 단언이 실패한다.
7. **T#15·T#16 검사의 예외와 회귀.** 이 태스크의 새 열 때문에 **아래 곳만** 바꾼다(PM이 허용한 예외, 이슈 #32 댓글 2026-10-14: "바꾼 곳은 계약서에 적은 곳뿐이어야 하고 증거에 `file:line`과 diff를 남긴다". 현재 위치: `ProjectListPage.test.tsx:108-114`(머리글), `:117-123`(그 테스트), `:14-39`(응답 고정값), `:102-108`(알파 행 셀 목록), `e2e/projects.spec.ts:100-108`): T#15 `ProjectListPage.test.tsx`의 머리글 다섯 단언(여섯으로)과 "does not draw 인력

## 격리

읽기 e2e와 스크린샷은 T#4의 `scripts/e2e-servers.sh`와 README "검사 격리" 표를 그대로 쓴다(백엔드 18080, 공유 DB `backend/data/e2e.db`, 프런트엔드 14173, 서버 기록 `.nexi-tmp/e2e-servers.pids`). **공유 DB에는 읽기
