# T#12 간트 차트 컴포넌트

## 산출물

배정 목록(프로젝트, 기간, 투입률)을 받아 겹치는 기간을 구분해 그리는 공용 간트 차트 컴포넌트 `Gantt`가 있다. 날짜 계산은 화면과 분리한 순수 함수로 두고, 컴포넌트 테스트와 1280px·360px 스크린샷이 있다.

## 작업량

이슈 #12 그대로 하나로 한다(나누지 않는다). 예상 약 4시간.

| 일 | 예상 |
|---|---|
| 날짜·겹침 계산 함수와 Vitest | 1시간 |
| 컴포넌트와 CSS, Vitest | 1.5시간 |
| 참조 화면의 표본 구역, e2e, 스크린샷 | 1시간 |
| 레드·그린 기록, 증거 | 0.5시간 |

## 전제

- 승인된 `docs/design/BRIEF.md`(3.6절 Gantt, 4절 Layout, 5절 Formats, 7절 Checks)와 토큰(`frontend/src/styles/tokens.css`)을 따른다. BRIEF가 정하지 않은 값은 아래에 `(제안)`으로 표시한다.
- 서버 API가 아직 없으므로 컴포넌트는 props만 받는다. 데이터를 가져오지 않는다. 직원 상세(T#14)와 배치 화면(T#17)이 이 컴포넌트를 가져다 쓴다.
- 입력 한 건: `{ id: string; projectName: string; projectStatus: '계획' | '진행 중' | '완료' | '보류'; start: 'YYYY-MM-DD'; end: 'YYYY-MM-DD'; rate: number }`. 기간은 양 끝 날짜를 포함한다(D18의 날마다 계산과 같은 기준). `rate`는 정수 %이고 값은 그대로 보여 준다(D36). 합계 계산은 화면에 보이는 배정의 `rate` 합이다. 종료된 프로젝트를 빼는 일(D19)은 이 컴포넌트가 하지 않고, 호출하는 화면이 정한다.
- 이 컴포넌트에는 화면을 하나 더 두지 않는다. e2e와 스크린샷은 T#4의 참조 화면 `/`에 "간트 차트" 구역(표본 상수)을 더해서 잰다. 업무 화면이 생기면 그 태스크들이 `/`를 가져간다. T#4의 `docs/screens/T4/`는 다시 찍지 않는다.

## 수용 기준

1. **날짜·겹침 계산.** `buildGanttModel(assignments, today)`(`frontend/src/components/gantt/model.ts`)가 순수 함수로 다음을 돌려준다. 날짜는 시간대와 무관하게 `YYYY-MM-DD` 문자열을 날짜 번호로 바꿔 계산한다.
   - 차트 구간: 가장 이른 시작일부터 가장 늦은 종료일까지(양 끝 포함)의 날짜 수.
   - 배정마다 구간 안의 시작 칸과 끝 칸. 줄 순서는 시작일, 종료일, 프로젝트명 순이다(제안).
   - 겹침 구간: 두 건 이상이 걸친 날짜를 합계가 같은 연속 구간으로 묶은 목록과 구간의 합계 %. 하루만 걸치는 경우(한 건의 종료일 = 다른 건의 시작일)도 겹침이고, 종료일 다음날 시작은 겹침이 아니다.
   - 오늘 칸: `today`가 차트 구간 안이면 그 칸, 밖이면 없음.
   - 월 눈금: 구간에 걸친 달마다 `max(그 달 1일, 구간 시작일)`의 칸과 `N월` 글자.
   - 확인: Vitest `frontend/src/components/gantt/model.test.ts`. 사례: 한 건; 겹치지 않는 두 건; 60%+30%가 부분 겹침(겹친 날에만 90%, 나머지 날은 겹침 없음); 세 건 겹침(합계가 구간마다 달라 구간이 나뉨); 종료일=시작일 하루 겹침; 종료일 다음날 시작은 겹침 없음; 오늘이 구간 밖; 입력 순서가 달라도 줄 순서가 같음; 두 해에 걸치는 구간의 월 눈금.
   - 준비: 빈 결과(`{ days: 0, rows: [], overlaps: [], ticks: [], todayIndex: null }`)를 돌려주는 스텁과 테스트. 레드: 첫 사례에서 `days`가 0이라 `toBe(…)` 단언이 실패한다.
2. **줄과 막대.** `Gantt`가 배정마다 한 줄을 그린다(BRIEF 3.6 Gantt).
   - 줄 머리에 프로젝트명을 쓴다. 막대는 `role="img"`이고 접근 이름이 `프로젝트명, 2026-10-01 ~ 2026-12-31, 60%`(5절 기간·투입률 형식)이다. 막대에도 같은 기간과 투입률을 보이는 글자로 쓴다. 막대 글자는 줄바꿈하고 말줄임표로 줄이지 않는다(BRIEF 5절 긴 값).
   - 막대는 `projectStatus`가 `진행 중`이면 `data-status="active"`, 그 밖이면 `data-status="other"`이다.
   - 확인: Vitest `Gantt.test.tsx`(줄 수, 접근 이름, `data-status`). 준비: `null`을 그리는 스텁. 레드: `getAllByRole('img')` 개수 단언이 실패한다.
   - 색은 e2e(기준 6)가 계산된 스타일로 확인한다.
3. **겹침 표시.** 겹침 구간 위에 그 구간의 합계 %를 xs 글자로 쓴다(예: `90%`). 겹침이 없는 구간에는 합계를 쓰지 않는다. 겹친 막대들은 서로 다른 줄에 있어 세로로 나뉘어 보인다.
   - 확인: Vitest `Gantt.test.tsx`. 60%+30% 부분 겹침이면 `90%` 라벨이 정확히 하나이고, 겹치지 않는 두 건이면 합계 라벨이 없다.
   - 준비·레드: 기준 2와 같다. 레드는 `getByText('90%')`가 없어 실패한다.
4. **오늘 표시.** `today`가 구간 안이면 1px danger 세로선과 "오늘" 글자를 그리고, 밖이면 그리지 않는다. `today`를 주지 않으면 브라우저의 오늘 날짜(로컬 `YYYY-MM-DD`)를 쓴다(제안: D19의 "서버 오늘"은 호출하는 화면이 `today`로 넘긴다).
   - 확인: Vitest `Gantt.test.tsx`(구간 안/밖에서 "오늘" 라벨의 유무). 색과 굵기는 기준 6의 e2e.
   - 준비·레드: 기준 2와 같다.
5. **월 눈금과 빈 상태.** 위쪽 축에 월 눈금(`10월`)을 쓴다. 배정이 없으면 차트 대신 `StateMessage` `empty`를 제목 "배치된 프로젝트가 없습니다"로 보여 준다(BRIEF 6.4 상태).
   - 확인: Vitest `Gantt.test.tsx`(눈금 글자, 빈 목록에서 제목과 `role="status"`).
   - 준비·레드: 기준 2와 같다.
6. **모양 (e2e, 참조 화면의 "간트 차트" 구역).** 표본은 서로 겹치는 세 건(그중 하나는 `완료` 프로젝트), 48자 영문 프로젝트명 하나, 오늘이 구간 안에 있는 `today`로 한다. 1280px와 360px에서 잰다.
   - 차트 너비 = 부모 너비(±1px).
   - `진행 중` 막대의 배경 `rgb(41, 82, 204)`·글자 `rgb(255, 255, 255)`; 그 밖의 막대의 배경 `rgb(238, 241, 245)`·글자 `rgb(26, 31, 39)`·테두리 1px `rgb(125, 135, 150)`.
   - 오늘 세로선: 너비 1px, 색 `rgb(191, 43, 27)`.
   - 48자 이름은 줄 머리 안에서 줄바꿈된다(그 요소의 `scrollWidth <= clientWidth`).
   - 1280px: 줄 머리(너비 160px, 제안)와 막대 칸이 한 줄에 있다. 360px: 프로젝트명이 막대 칸 위에 놓인다(제안).
   - 확인: Playwright `frontend/e2e/gantt.spec.ts`. 준비: 참조 화면에 구역 자리만 둔 스텁(`data-testid="gantt"`가 없는 상태). 레드: `locator('[data-testid="gantt"]')` 개수가 0이라 `toBe(1)`이 실패한다. 개수로 즉시 판정한다.
7. **반응형 (D29, D34).** 같은 참조 화면이 1280px, 1024px, 1023px, 360px에서 가로 넘침이 없다. T#4의 `expectNoHorizontalOverflow`(`frontend/e2e/support/layout.ts`)를 쓴다.
   - 확인: Playwright `frontend/e2e/gantt.spec.ts`. 준비·레드: 기준 6과 같다.
8. **스크린샷.** `make screenshots T=12`가 `docs/screens/T12/gantt-1280.png`와 `docs/screens/T12/gantt-360.png`를 저장한다. 각 너비에서 간트 구역(`data-testid="gantt"`)이 하나 있음을 단언한 뒤 구역만 찍는다.
   - 확인: `frontend/e2e/screens/T12.spec.ts`, `make screenshots T=12; echo $?`가 0이고 두 PNG가 있다. 이어서 T#4 기준 11(a)처럼 `.nexi-tmp/e2e-servers.pids`의 프로세스 그룹이 모두 없고 18080·14173에 응답이 없다.
   - 준비·레드: 스펙 파일이 없는 상태에서 `make screenshots T=12`가 `screenshots: frontend/e2e/screens/T12.spec.ts 없음`으로 실패하는 것은 레드가 아니다. 스펙을 만든 뒤 구역이 없어 개수 단언이 실패하고 PNG가 생기지 않는 것이 레드다.
9. **회귀.** `make build`, `make test`, `make lint`가 통과한다. T#4의 `design-system.spec.ts`와 `App.test.tsx`는 고치지 않고 통과한다. 참조 화면에 구역을 더해도 T#4 e2e의 측정(가로 넘침, 숫자 열 정렬 등)이 그대로 통과한다.

## 검증 명령

  - `npm --prefix frontend run test`: 기준 1–5의 새 테스트 파일(`model.test.ts`, `Gantt.test.tsx`).
  - `npm --prefix frontend run test:e2e`: `gantt.spec.ts`. 기준 6–7.
  - `make screenshots T=12`. 기준 8.
  - 각 검사의 준비와 레드 단언은 위 기준에 적었다.
- 회귀 검사: `make build`, `make test`, `make lint`는 작업 전후에 통과한다. 작업 후의 `make test`에는 새 Vitest와 e2e가 들어간다.

## 격리

새로 건드리는 DB·폴더·서비스·포트는 없다. e2e와 스크린샷은 T#4가 만든 `scripts/e2e-servers.sh`와 README "검사 격리" 표를 그대로 쓴다(백엔드 18080, DB 파일 `backend/data/e2e.db`, 프런트엔드 14173, 서버 기록 `.nexi-tmp/e2e-servers.pids`). 외부 네트워크를 쓰지 않는다(D40). 기계별 설치 경로나 PATH 설정을 쓰지 않는다.

## 하지 않을 일

- 서버 API 호출, 배정 데이터 조회, 가용률 계산(→ T#7, T#10, T#14, T#17). 합계는 화면에 넘겨받은 `rate`의 합일 뿐이다.
- 종료된 프로젝트를 걸러 내는 일(D19), 100% 초과 경고 표시(→ 배치 화면 T#17).
- 직원 상세와 배치 화면에 간트를 끼우는 일(→ T#14, T#17).
- 확대·축소, 드래그로 기간 바꾸기, 막대 클릭 이동, 툴팁 등 상호작용.
- 외부 차트 라이브러리 도입. 막대와 눈금은 DOM과 CSS(토큰)로 그린다.
- `docs/screens/T4/` 다시 찍기, T#4 계약서·증거·리뷰 수정.
- 스크린샷 픽셀 비교 자동화. 스크린샷은 리뷰어가 BRIEF와 대조한다.
- 백엔드 코드 변경.

## 화면

`docs/design/BRIEF.md` 3.6절 Gantt, 4절 Layout, 5절 Formats를 따른다. `make screenshots T=12`가 찍는 화면:

- `docs/screens/T12/gantt-360.png`: 같은 구역, 너비 360px(구역 너비 328px).
