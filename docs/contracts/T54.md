# T#54 변경: 직원·시드 트랜잭션과 SQLite 동시성

## 산출물

SQLite WAL 모드 및 busy_timeout 설정이 적용되고, 핵심 직원 관리 및 시드 주입 로직에 트랜잭션 경계가 설정된 백엔드 시스템.

## 수용 기준

1. SQLite WAL 모드가 활성화되어 읽기와 쓰기가 서로를 차단하지 않는다 — 확인: `./data/app.db-wal` 파일 존재 여부
2. `SeedRunner.run()` 실행 중 예외 발생 시 모든 시드 데이터가 롤백된다 — 확인: 예외 발생 후 DB 테이블의 행 수가 0인지 확인하는 통합 테스트
3. `EmployeeService.register()` 실행 중 기술 정보 삽입 단계에서 예외 발생 시 직원 정보도 함께 롤백된다 — 확인: `Employee`와 `EmployeeSkill` 테이블의 상태를 검사하는 통합 테스트
4. 동시 쓰기 요청 발생 시 `busy_timeout` 동안 대기하여 `SQLITE_BUSY` 에러 없이 처리가 완료된다 — 확인: 멀티스레드 환경에서 동일 레코드 수정을 시도하는 동시성 테스트

## 검증 명령

- 새 검사: `./gradlew test --tests "com.ax.rms.concurrency.SqliteConcurrencyTest"` — 현재는 `SQLITE_BUSY` 또는 데이터 불일치로 인해 실패해야 함
- 회귀 검사: make test, make lint, make build — 기존 기능 유지 확인

## 하지 않을 일

- `SQLITE_BUSY` 에러의 클라이언트 응답 코드 변경(409 등으로 변환) — 이는 오류 처리 이슈에서 담당함
- DB 스키마 자체의 변경 (테이블 구조 수정 등)
