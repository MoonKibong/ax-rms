# T#38 직원 상세·내 정보 (읽기)

## 산출물

관리자가 `/employees/<id>`에서 한 직원의 기본 정보·기술·배치 현황(간트와 표)·현재 가용률을 API 값 그대로 보고, 로그인한
누구나 `/me`에서 자기 상세를 같은 모양으로 읽기 전용으로 보며, 직원 목록의 이름이 그 상세로 가는 링크인 화면이 있다.

  응답에 `today`를 더한다(아래 "API 변경"). `Gantt`의 배정 `projectStatus`는 한국어(`계획`, `진행 중`, `완료`, `보류`)로 받는다.
- **#13이 넘긴 일.** #13 계약서 "하지 않을 일"이 이름의 상세 링크를 상세 화면 태스크에 넘겼다. 그래서 #13 검사 중 "링크가 없다"
  단언 둘을 바꾼다(기준 6, 12). "직원 등록" 버튼은 #39의 몫이다.
- **#39와의 경계.** 이 태스크의 상세와 내 정보에는 버튼이 없다. 등록·수정 폼, 상태 변경 대화상자, "직원 등록"·"수정"·"상태 변경"
  버튼, `GET /api/departments`, `SelectField` 오류 표시, `Dialog`는 #39가 이 화면에 더한다.
- 권한(D9, D25)은 #6의 라우트 보호와 서버 권한 표 그대로다. 이 태스크는 읽기만 하고 권한 표를 바꾸지 않는다.
  - 인력 관리자·프로젝트 관리자·겸임: 모든 직원의 상세(`/employees/:id`, `GET /api/employees/{id}`)와 자기 내 정보(`/me`)를 읽는다.
  - 직원만 가진 계정: 자기 내 정보(`/me`, `GET /api/me/employee`)만 읽는다. `/employees/:id`를 열면 `/me`로 가고, 서버는 그 계정의
    `GET /api/employees/{id}`를 403으로 막는다(자기 id 포함, #6).
  - 이 태스크로 바뀌는 데이터는 없다.
- e2e DB(`backend/data/e2e.db`)는 한 번 만든 뒤 계속 쓰고, 시드 날짜는 그 DB를 만든 날 기준이다. 그래서 실제 시드로 하는 e2e는
  날짜·가용률을 외워 단언하지 않고 같은 순간의 API 응답과 대조한다. 숫자 형식·상태·서버의 오늘은 고정 응답으로 확인한다.

## API 변경 (백엔드)

- `EmployeeDetailResponse` 끝에 `today`(`LocalDate`, JSON `"2026-06-15"` 꼴)를 더한다. 값은 같은 응답의
  `currentAvailability`와 `needsReview`를 계산한 `LocalDate.now(clock)` 그대로다.
- 이 응답을 쓰는 `GET /api/employees/{id}`, `GET /api/me/employee`, 그리고 `POST /api/employees`(201)·`PUT /api/employees/{id}`·
  `PATCH /api/employees/{id}/status`의 본문이 모두 `today`를 갖는다. 다른 키·값·순서와 목록 응답(`GET /api/employees`)은 바꾸지
  않는다. 새 경로와 권한 변경은 없다.

## 화면 동작

### 경로 (D16, D24, D25)

| 경로 | 비로그인 | 직원만 | 관리자(인력·프로젝트·겸임) |
|---|---|---|---|
| `/employees/:id` | `/login`으로 | `/me`로 | 상세 |
| `/me` | `/login`으로 | 내 정보 | 내 정보(메뉴에는 없다, #6) |

- `:id`는 `^[1-9][0-9]*$`여야 한다. 아니면(예: `/employees/abc`, 그리고 #39가 등록 경로를 더하기 전의 `/employees/new`) 요청을
  보내지 않고 StateMessage `error`, 설명 "직원을 찾을 수 없습니다."를 보인다 (제안). `/employees/:id/edit` 같은 다른 주소는 #6의
  "그 밖의 경로" 규칙 그대로다.
- 셸의 현재 항목은 `/employees/:id`에서 "직원", `/me`에서 "내 정보"다.

### 상세 `/employees/:id` (BRIEF 6.4)

구역 제목은 h2 lg/600, 구역 사이는 `--space-6`(32px)이다(BRIEF 6.0의 구역 규칙을 따름, 제안).

1. **머리**: 이름(h1, xl/700). 그 아래 한 줄(`flex-wrap`, 간격 `--space-2`): 상태 `Badge`(`투입 가능`/`투입 불가`),
   `needsReview`가 참이면 `확인 필요` `Badge`(제안, D21), "현재 가용률"(sm, text-muted)과 값 `40%`(sm/600, `tabular-nums`).
2. **기본 정보**(h2): `dl` 줄마다 라벨(`dt`, sm/600 text-muted, 너비 120px)과 값(`dd`, md/400 text, `overflow-wrap: anywhere`)
   (제안). 순서: 부서, 직무, 경력(`5년`), 투입 불가 사유, 종료 예정일(`YYYY-MM-DD`). 값이 `null`이면 `—`(text-muted).
3. **기술**(h2): `ul`, 줄마다 `Java · 고급`(API 순서, 숙련도 `초급`·`중급`·`고급`, D11). 없으면 `—`.
4. **배치 현황**(h2): `Gantt`, 그 아래 `DataTable` 프로젝트 · 기간 · 투입률(API 순서 = `startDate` 오름차순).
   - 간트 입력: 배정마다 `{id: "<projectId>-<startDate>", projectName, projectStatus, start: startDate, end: endDate,
     rate: allocationPercent}`. `projectStatus`는 `PLANNED`→`계획`, `IN_PROGRESS`→`진행 중`, `DONE`→`완료`,
     `ON_HOLD`→`보류`. `today`는 응답의 `today`다. 종료된 프로젝트의 배정도 그대로 넘긴다(#8, D15).
   - 표: 프로젝트명은 일반 글자(프로젝트 상세 링크는 #16), 기간 `2026-09-23 ~ 2026-11-22`, 투입률 `60%`(끝 정렬,
     `tabular-nums`).
   - 배치가 없으면 간트의 `empty` "배치된 프로젝트가 없습니다" 하나만 보이고 표는 그리지 않는다(BRIEF 6.4 상태).
- 버튼은 없다(→ #39).

### 내 정보 `/me` (D24)

셸 안에 h1 "내 정보"(#6의 제목을 그대로 둔다), 그 아래 `GET /api/me/employee`로 받은 같은 상세를 그린다. 이름은 h2이고 모양은
상세의 이름과 같다(xl/700). 어떤 역할에도 버튼이 없다. `GET /api/employees/…`는 부르지 않는다.

### 목록 `/employees`의 변경 (#13 → 이 태스크)

- 이름 칸(좁은 구간의 카드 제목 포함)이 `/employees/{id}`로 가는 링크(`a`)다. 글자색 primary(BRIEF 2.1 링크 대비 6.62), hover
  밑줄 (제안). 행 전체 클릭은 두지 않는다.
- #13의 검색·필터·주소·상태·지연 응답 동작은 바꾸지 않는다.

### 불러오는 동안과 상태 (BRIEF 6절, 3.3)

- 불러오는 중: 내용 자리에 `Spinner` 24px와 "불러오는 중…"(sm, text-muted), 그 영역에 `aria-busy="true"`.
- 오류: 네트워크 오류이거나 2xx가 아니면(401 포함) StateMessage `error`(설명은 API `message`, 없으면 BRIEF 기본)와 "다시 시도".
  다시 시도는 같은 요청을 다시 보낸다. 404의 설명은 API 메시지 "직원을 찾을 수 없습니다."다.
- 주소의 id가 바뀌면 앞 요청을 끊고(`AbortController`) 그 응답이 나중에 와도 화면을 바꾸지 않는다.

## 격리

격리" 표 그대로다(백엔드 18080, DB 파일 `backend/data/e2e.db`, 프런트엔드 14173, 서버 기록 `.nexi-tmp/e2e-servers.pids`). e2e는
